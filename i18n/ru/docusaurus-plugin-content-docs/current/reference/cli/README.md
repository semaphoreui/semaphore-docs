# CLI

Бинарный файл `semaphore` — это одновременно и сервер, и полноценный инструмент
администрирования. Запустите его без аргументов (или `semaphore help`), чтобы
увидеть список всех команд:

```bash
semaphore help
```

Полный сгенерированный список всех команд и флагов приведён в
[справочнике команд](/reference/cli/commands). Для большинства административных задач
есть отдельная группа команд:

| Группа команд | Назначение |
|---------------|---------|
| [`semaphore users`](/reference/cli/users) | Добавление, изменение, удаление и просмотр пользователей; управление API-токенами и TOTP (2FA). |
| [`semaphore projects`](/reference/cli/projects) | Экспорт и импорт проектов (резервные копии). |
| [`semaphore vaults`](/reference/cli/vaults) | Перешифрование хранимых секретов и проверка использования ключей шифрования. |
| [`semaphore runner`](/reference/cli/runners) | Запуск в режиме runner'а и регистрация/отмена регистрации runner'ов. |
| [`semaphore migrate`](/reference/cli/migrations) | Применение или откат миграций базы данных. |

У некоторых групп команд есть более короткие псевдонимы: `users`/`user`, `projects`/`project`,
`vaults`/`vault` и `server`/`service`.

:::info
Каждая команда, работающая с базой данных (`users`, `projects`, `vaults`, `migrate`,
`server`), перед выполнением применяет все ожидающие миграции схемы. Сделайте
резервную копию базы данных, прежде чем запускать CLI более новой версии Semaphore
против существующей базы данных.
:::

## Глобальные опции {#global-options}

Эти флаги принимает каждая команда:

| Опция | Описание |
|--------|-------------|
| `--config <path>` | Путь к файлу конфигурации. |
| `--no-config` | Не читать файл конфигурации — использовать только переменные окружения. |
| `--log-level <level>` | Уровень детализации логов: `DEBUG`, `INFO`, `WARN`, `ERROR`, `FATAL` или `PANIC`. По умолчанию берётся из переменной окружения `SEMAPHORE_LOG_LEVEL`. |
| `--debug-filter <spec>` | Ограничивает вывод `DEBUG` определёнными пространствами имён, например `'runner,task_*'` или `'*,-db'`. Действует только при уровне логирования `DEBUG`. По умолчанию берётся из `SEMAPHORE_DEBUG_FILTER`. |

### Как находится файл конфигурации {#how-the-configuration-file-is-found}

Если `--config` не указан, Semaphore ищет файл в следующем порядке и использует
первый найденный:

1. Путь из переменной окружения `SEMAPHORE_CONFIG_PATH`.
2. `config.json`, `config.yaml` или `config.yml` в текущем каталоге.
3. `/usr/local/etc/semaphore/config.json` (или `.yaml` / `.yml`).
4. `/etc/semaphore/config.json` (или `.yaml` / `.yml`).

Переменные окружения применяются поверх файла, то есть переопределяют значения
из файла. С `--no-config` используются только переменные окружения и значения по
умолчанию. Полный список опций см. в разделе
[Конфигурация](/admin-guide/configuration).

## Версия {#version}

Вывести текущую версию.

```bash
semaphore version
```

## Интерактивная настройка {#interactive-setup}

Используйте её для первоначальной настройки. Она генерирует секреты, проводит
через интерактивный опросник, записывает файл конфигурации, выполняет миграции
базы данных и создаёт первого пользователя-администратора.

```bash
semaphore setup
```

Передайте `--config <path>`, чтобы указать, куда записать файл конфигурации.
Без него setup запросит выходной каталог (по умолчанию — текущий каталог) и
запишет туда `config.json`.

Если введённые имя пользователя или email уже существуют, setup оставит
существующего пользователя вместо создания нового.

По завершении выводятся команды для запуска сервера, например:

```bash
./semaphore server --config /path/to/config.json
```

## Режим сервера {#server-mode}

Запустить сервер Semaphore (веб-интерфейс и API). `service` — псевдоним `server`.

```bash
semaphore server --config /path/to/config.json
```

При запуске сервер применяет ожидающие миграции базы данных и выводит
используемые базу данных, временный путь, интерфейс и порт.

## Режим runner'а {#runner-mode}

Запустить Semaphore как runner для выполнения задач. Полный набор подкоманд
(`setup`, `register`, `start`, `unregister`) см. в разделе
[Runner'ы](/reference/cli/runners).

```bash
semaphore runner start --config /path/to/runner-config.json
```

## Миграция базы данных {#database-migration}

Привести схему базы данных в актуальное состояние. О применении или откате до
конкретной версии см. в разделе
[Миграции базы данных](/reference/cli/migrations).

```bash
semaphore migrate --config /path/to/config.json
```

# Хранилище секретов CyberArk <Enterprise />

Semaphore UI Enterprise может использовать **CyberArk Privileged Access Manager** (PAM Self-Hosted или Privilege Cloud) в качестве внешнего хранилища секретов Key Store вместо базы данных. Semaphore взаимодействует с REST API Password Vault Web Access (PVWA): каждый ключ Semaphore сопоставляется с **учётной записью** CyberArk внутри **Safe**.

## Параметры конфигурации {#configuration-options}

При создании хранилища **CyberArk** в разделе **Key Store → Storages** настройте:

| Поле | Описание |
|------|----------|
| **URL сервера** | Базовый адрес PVWA, например `https://pvwa.example.com`. Завершающий путь `/PasswordVault` поддерживается. Обязательно. |
| **Пропустить проверку TLS-сертификата** | Отключает проверку сертификата. Только для тестовых сред. |
| **Метод аутентификации** | Метод входа PVWA для пользователя Semaphore: `CyberArk` (по умолчанию), `LDAP`, `RADIUS` или `Windows`. |
| **Имя пользователя** | Пользователь PVWA, под которым входит Semaphore. Обязательно. |
| **Пароль** | Пароль этого пользователя. Может храниться в базе данных, считываться из переменной окружения или загружаться из файла. |
| **Safe по умолчанию** | Safe, используемый, когда ключ ссылается на аккаунт без префикса Safe, а также путь синхронизации по умолчанию. |
| **ID платформы для новых аккаунтов** | Платформа, назначаемая аккаунтам, создаваемым Semaphore (например, `UnixSSH`). Требуется, только если хранилище не доступно только для чтения и вы создаёте ключи из Semaphore. |
| **Адрес для новых аккаунтов** | Необязательное свойство адреса для аккаунтов, создаваемых Semaphore. Требуется для некоторых платформ. |

Хранилище может работать в режиме «только чтение». В этом режиме Semaphore только считывает и синхронизирует учётные записи и никогда не создаёт, не обновляет и не удаляет данные в Vault.

### Необходимые разрешения PVWA {#required-pvwa-permissions}

Предоставьте пользователю Semaphore следующие разрешения для каждого используемого Safe:

| Операция | Разрешения Safe |
|----------|-----------------|
| Чтение ключа, синхронизация | **Список учётных записей**, **Получение учётных записей** |
| Создание ключа из Semaphore | **Добавление учётных записей** |
| Обновление ключа из Semaphore | **Обновление значения пароля**, **Обновление свойств учётной записи** |
| Удаление ключа из Semaphore | **Удаление учётных записей** |

Semaphore всегда запрашивает параллельную сессию PVWA (`concurrentSession`), поэтому несколько узлов Semaphore или выполняющаяся задача и плановая синхронизация могут совместно использовать одного пользователя без разрыва сессий. Для этого требуется PVWA 11.3 или новее.

:::warning
Не включайте требование указания причины («require reason») или интеграцию с тикет-системами для сейфов, используемых Semaphore. Semaphore отправляет фиксированную причину, но не может передавать номера тикетов.
:::

## Как использовать {#how-to-use}

1. В проекте откройте **Key Store → Storages** и создайте хранилище **CyberArk**.
2. При создании или редактировании ключа выберите это хранилище и укажите учётную запись как `Safe/AccountName`. Имя учётной записи — это имя объекта, отображаемое в PVWA. Если у хранилища задан Safe по умолчанию, достаточно указать только `AccountName`.
3. При необходимости настройте [пути синхронизации](/user-guide/key-store/secret-sync) для автоматического импорта целых сейфов по расписанию.

### Сопоставление типов ключей {#key-type-mapping}

| Тип ключа Semaphore | Учётная запись CyberArk |
|---------------------|-------------------------|
| **Вход по паролю** | Аккаунт пароля: `userName` становится логином, секрет аккаунта — паролем. |
| **SSH** | Аккаунт ключа (`secretType: key`): `userName` становится логином, секрет аккаунта — приватным ключом. SSH-ключи с парольной фразой не могут храниться в CyberArk. |
| **Секрет / строка** | Аккаунт пароля без имени пользователя. Секрет аккаунта используется как есть. |

Когда Semaphore создаёт учётную запись, автоматическое управление Central Policy Manager (CPM) отключается, чтобы CyberArk не менял секрет, который Semaphore только что записал. Если требуется, чтобы CyberArk ротировал учётные данные, управляйте аккаунтом из PVWA и отметьте хранилище в Semaphore как доступное только для чтения.

## Синхронизация секретов {#syncing-secrets}

Путь синхронизации — это имя Safe. Semaphore импортирует каждую учётную запись Safe как ключ с именем аккаунта (с необязательным префиксом). Тип ключа определяется по учётной записи: аккаунты ключей становятся ключами SSH, аккаунты паролей с именем пользователя — ключами входа по паролю, а аккаунты без имени пользователя — простыми секретами. См. [Синхронизация секретов из удалённых хранилищ](/user-guide/key-store/secret-sync).

# Задачи

Задача — это одно выполнение [шаблона задачи](./task-templates): один запуск playbook Ansible, конфигурации Terraform/OpenTofu/Terragrunt либо скрипта Bash, PowerShell или Python. У каждой задачи есть собственные лог, статус и подробности, поэтому всегда видно, что было запущено, когда, кем и с какой ревизией репозитория.

## Запуск задачи {#starting-a-task}

Вам нужна роль **Task Runner** или выше в проекте (см. [Команды](./team)). Запустить задачу можно двумя способами:

- В разделе **Task Templates** нажмите кнопку **воспроизведения** в строке шаблона.
- На странице шаблона нажмите кнопку в правом верхнем углу. Её название зависит от типа шаблона: **Run**, **Build** или **Deploy**.

Оба способа открывают диалог **New Task**. Его содержимое зависит от приложения и от опций, включённых в шаблоне.

![Диалог New Task для шаблона Ansible](/assets/task-new-ansible.webp)

| Поле | Для каких шаблонов | Описание |
|---|---|---|
| **Message** | всех шаблонов | Необязательная заметка, которая сохраняется вместе с задачей и отображается в истории и уведомлениях. |
| **Build Version** | шаблонов deploy | Какую сборку разворачивать. По умолчанию выбрана последняя успешная сборка. См. [Шаблоны сборки и развёртывания](./task-templates/build-deploy). |
| Переменные опроса | шаблонов с [переменными опроса](./task-templates/survey-vars) | По одному полю на переменную; обязательные переменные необходимо заполнить. |
| **Dry Run** `--check`, **Diff** `--diff` | Ansible | Запустить playbook в режиме проверки или показать изменения файлов. Остальные подсказки Ansible (Limit, Tags, Skip tags, Debug) появляются, если включены в шаблоне, см. [Подсказки](./task-templates/prompts). |
| **Plan**, **Destroy**, **Auto Approve**, **Upgrade**, **Reconfigure** | Terraform, OpenTofu, Terragrunt | Выполнить только `plan` либо добавить `-destroy`, `-auto-approve`, `-upgrade` или `-reconfigure`. См. [Terraform/OpenTofu](./apps/terraform). |
| **Branch**, **Inventory**, **CLI args** | любого приложения | Переопределить значения шаблона для этого запуска. Каждое переопределение должно быть разрешено в настройках шаблона. |

![Диалог New Task для шаблона Terraform](/assets/task-new-terraform.webp)

Нажмите **Run** (или **Build** / **Deploy**), чтобы поставить задачу в очередь.

### Очередь и параллельное выполнение {#queue-and-parallel-execution}

Задачи одного шаблона выполняются последовательно, если в шаблоне не включена опция **Allow parallel tasks**. Кроме того, проект может ограничивать общее число выполняемых задач параметром **Max number of parallel tasks** в [настройках проекта](./projects/settings). Задача, которой приходится ждать, остаётся в статусе `waiting` и запускается автоматически, когда освобождается место.

## Окно задачи {#task-window}

Щелчок по задаче в любом месте интерфейса открывает окно задачи. В заголовке отображаются шаблон, номер задачи, сообщение коммита использованной ревизии репозитория, значок статуса, кто и когда запустил задачу, а также длительность. Значок со стрелками разворачивает окно на весь экран.

![Лог задачи](/assets/task-log.webp)

| Вкладка | Содержимое |
|---|---|
| **Log** | Вывод задачи в реальном времени с отметками времени. Пока задача выполняется, лог передаётся потоком. **Raw log** открывает необработанный вывод в новой вкладке браузера. |
| **Details** | Сведения о шаблоне (приложение, шаблон), сведения о коммите (сообщение и хеш) и сведения о запуске: сообщение, время создания, начала и окончания, длительность, а также, если заданы, раннер, ветка, ограничение limit и переменные, использованные при запуске. |
| **Summary** (Pro) | Для задач Ansible: сколько хостов завершилось успешно и сколько с ошибкой, с таблицей неуспешных задач по серверам. |

![Подробности задачи](/assets/task-details.webp)

## Статусы задач {#task-statuses}

| Статус | Значение |
|---|---|
| `waiting` | Задача в очереди: выполняется другая задача того же шаблона, достигнут лимит проекта или пока нет доступного раннера. |
| `starting` | Раннер взял задачу и готовит репозиторий и окружение. |
| `waiting_confirmation` | Инструмент задал вопрос и ждёт пользователя, например `terraform apply` без **Auto Approve** или скрипт, читающий ввод. Используйте **Confirm** или **Reject** в окне задачи. |
| `confirmed` | Пользователь подтвердил запрос, задача продолжается. |
| `rejected` | Пользователь отклонил запрос, задача завершается. |
| `running` | Playbook или скрипт выполняется. |
| `stopping` | Запрошена остановка, процесс завершается. |
| `stopped` | Задача остановлена пользователем. |
| `success` | Завершилась с кодом возврата 0. |
| `error` | Завершилась с ненулевым кодом возврата или не смогла запуститься. В интерфейсе отображается как **Failed**. |

## Остановка задач {#stopping-tasks}

Откройте окно выполняющейся задачи и нажмите **Stop**. Semaphore отправляет сигнал завершения, и задача переходит в статус `stopping`, пока процесс завершается. Если процесс не реагирует, кнопка меняется на **Force Stop**; нажмите её, чтобы немедленно завершить процесс.

Чтобы остановить все выполняющиеся и стоящие в очереди задачи одного шаблона, откройте страницу шаблона и воспользуйтесь кнопкой **Stop all**. В выпадающем меню доступны **Stop** и **Force stop**.

## Повторный запуск задачи {#running-a-task-again}

На вкладке **Tasks** шаблона в каждой строке есть кнопка **повторного запуска**. Она открывает диалог New Task с уже заполненными сообщением и параметрами этой задачи.

![Задачи шаблона с кнопками повторного запуска](/assets/template-tasks.webp)

## Где искать задачи {#where-tasks-are-listed}

- **Dashboard → History**: все задачи проекта, см. [История](./projects/history).
- **Страница шаблона → Tasks**: задачи одного шаблона.
- **Task Templates**: разверните строку стрелкой слева, чтобы увидеть последние задачи шаблона, не покидая список.

## Хранение логов {#log-retention}

По умолчанию задачи и логи хранятся бессрочно. Используйте `max_tasks_per_template`, чтобы оставлять только последние задачи каждого шаблона, см. [История](./projects/history#task-retention).

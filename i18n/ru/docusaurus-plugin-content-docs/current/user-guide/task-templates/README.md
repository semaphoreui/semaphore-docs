# Шаблоны задач

Шаблон задачи описывает, что и как запускать: приложение, репозиторий и исполняемый файл, инвентарь, группы переменных, учётные данные и опции, которые пользователь может изменить при запуске задачи. Каждая [задача](../tasks) создаётся из шаблона.

Шаблоны поддерживают следующие приложения:

* [Ansible](/user-guide/apps/ansible)
* [Terraform/OpenTofu](/user-guide/apps/terraform) и [Terragrunt](/user-guide/apps/terragrunt)
* [Shell](/user-guide/apps/bash)
* [PowerShell](/user-guide/apps/powershell)
* [Python](/user-guide/apps/python)

Администраторы могут включать и отключать приложения, а также добавлять свои, см. [Приложения](/user-guide/apps).

## Список шаблонов {#template-list}

Раздел **Task Templates** содержит все шаблоны проекта.

![Список шаблонов](/assets/templates-list.webp)

| Столбец | Содержимое |
|---|---|
| **Name** | Имя шаблона со значком приложения. Кнопка **воспроизведения** запускает новую задачу. |
| **Version** | Последняя версия сборки для шаблонов build и deploy, для остальных — значок результата последней задачи. |
| **Status** | Значок статуса последней задачи либо *Not launched*. |
| **Last Task** | Номер последней задачи и кто её запустил. |
| **Playbook** | Файл, который запускает шаблон. |
| **Inventory**, **Variable Groups**, **Repository** | Ресурсы, привязанные к шаблону. |

Вкладки над списком — это [представления](./views): именованные группы шаблонов. Значок шестерёнки в правом верхнем углу позволяет выбрать отображаемые столбцы. Щёлкните по стрелке слева от строки, чтобы развернуть последние задачи этого шаблона.

![Развёрнутая строка шаблона](/assets/templates-list-expanded.webp)

## Страница шаблона {#template-page}

Щёлкните по имени шаблона, чтобы открыть его страницу. Кнопка в правом верхнем углу запускает задачу (**Run**, **Build** или **Deploy** в зависимости от типа), а **Stop all** останавливает все выполняющиеся и стоящие в очереди задачи шаблона.

| Вкладка | Содержимое |
|---|---|
| **Tasks** | Задачи этого шаблона с кнопкой **повторного запуска** в каждой строке. |
| **Details** | Playbook, тип, инвентарь, группы переменных и репозиторий, а также диаграмма статусов задач с теми же фильтрами, что и в [Статистике](../projects/stats). |
| **Workspaces** | Только для шаблонов Terraform, OpenTofu и Terragrunt: список рабочих пространств, см. [Рабочие пространства](../apps/terraform/workspaces). |

![Подробности шаблона](/assets/template-details.webp)

## Типы шаблонов {#template-types}

| Тип | Назначение |
|---|---|
| **Task** | Обычный запуск. Тип по умолчанию. |
| **Build** | Создаёт артефакт и присваивает ему автоматически увеличивающуюся версию. |
| **Deploy** | Разворачивает версию, созданную шаблоном сборки. |

Шаблоны сборки и развёртывания, а также переменная `semaphore_vars`, которую они передают в playbook, описаны в разделе [Шаблоны сборки и развёртывания](./build-deploy).

## Форма шаблона {#template-form}

Пользователи с ролью **Manager** и выше могут создавать и изменять шаблоны с помощью кнопки **New Template** и значка карандаша. Форма разбита на следующие группы. Поля, отмеченные названием приложения, отображаются только для него.

### Общие поля {#common-fields}

| Поле | Описание |
|---|---|
| **Name** | Обязательное. Имя шаблона. |
| **Description** | Необязательный текст, отображаемый под именем. |
| **App** | Запускаемое приложение. |
| **Repository** | Репозиторий с playbook или скриптом, см. [Репозитории](../repositories). |
| **Branch** | Ветка Git, которую нужно выгрузить. Пустое значение означает ветку, заданную в репозитории. |
| **Playbook / Script filename** | Путь к файлу относительно корня репозитория. Для приложений Terraform — подкаталог с конфигурацией. |
| **Different working directory** | Запускать инструмент из другого каталога репозитория. |
| **Inventory** | Инвентарь Ansible либо рабочее пространство для приложений Terraform. |
| **Variable Groups** | Одна или несколько групп переменных, чьи переменные и секреты передаются в задачу, см. [Группы переменных](../environment). |
| **Vault password** (Ansible) | Ключи для расшифровки Ansible Vault, см. [Несколько паролей vault](../apps/ansible#multiple-vault-passwords). |
| **View** | На какой вкладке [представления](./views) показывать шаблон. |
| **CLI args** | Дополнительные аргументы командной строки в виде JSON-массива, например `["-vvv"]`. |

### Поля, зависящие от типа {#type-specific-fields}

| Поле | Тип | Описание |
|---|---|---|
| **Start Version** | Build | Первая присваиваемая версия, например `1.0.0`. |
| **Build Template** | Deploy | Шаблон сборки, артефакты которого разворачивает этот шаблон. |
| **Autorun** | Deploy | Запускать развёртывание автоматически после каждой успешной сборки. |

### Дополнительные опции {#advanced-options}

| Поле | Описание |
|---|---|
| **Allow parallel tasks** | Разрешить одновременное выполнение нескольких задач этого шаблона, см. [Параллельные задачи](#parallel-tasks). |
| **Alerts**, **Send on success**, **Send on error** | Отправлять ли уведомления по задачам этого шаблона и при каких результатах. Для уведомлений также требуется включённая опция **Allow alerts for this project** в [настройках проекта](../projects/settings). |
| **Runner tag** (Pro) | Выполнять задачи только на раннерах с этим тегом, см. [Раннеры проекта](../projects/runners). |
| **Executor image** | Образ контейнера для раннеров Docker и Kubernetes, см. [Образ исполнителя](#executor-image-docker-and-kubernetes-runners). |
| **Issue JWT to task runner**, **JWT audience**, **JWT TTL** | Выдавать задаче подписанный токен, см. [JWT для задач](./jwt). |
| **Auto-run task if new git commit have been found** | Опрашивать репозиторий с заданным интервалом и запускать задачу при появлении новых коммитов в ветке. |
| **Survey variables** | Поля, которые пользователь заполняет при запуске задачи, см. [Переменные опроса](./survey-vars). |

### Подсказки {#prompts}

Подсказки (prompts) — это флажки, позволяющие пользователю изменять встроенные опции в диалоге New Task: ветку, инвентарь, аргументы командной строки, а для Ansible — limit, теги, пропускаемые теги, уровень отладки и установку Galaxy. См. [Подсказки](./prompts).

### Опции приложений {#application-options}

- **Ansible**: limit, теги, пропускаемые теги и опции установки Galaxy, см. [Ansible](../apps/ansible).
- **Terraform/OpenTofu/Terragrunt**: автоматическое подтверждение и переопределение backend, см. [Terraform/OpenTofu](../apps/terraform) и [HTTP backend](../apps/terraform/states).

## Параллельные задачи {#parallel-tasks}

По умолчанию задачи одного шаблона выполняются последовательно. Чтобы разрешить одновременные запуски одного и того же шаблона, включите опцию «Allow parallel tasks» в настройках шаблона.

## Образ исполнителя (раннеры Docker и Kubernetes) {#executor-image-docker-and-kubernetes-runners}

Когда раннер проекта использует исполнитель **Docker** (Pro) или **Kubernetes** (Enterprise), каждая задача обычно выполняется в образе задания по умолчанию, заданном на раннере (например, `semaphoreui/job:latest`). Этот образ можно переопределить для отдельного шаблона.

1. Откройте настройки шаблона
2. Укажите в поле **Executor image** ссылку на образ контейнера (например, `my-registry/ansible:2.16` или `semaphoreui/job:latest`)
3. Сохраните шаблон

**Поведение**:
- Это поле учитывают только исполнители раннера **Docker** и **Kubernetes**; локальный исполнитель его игнорирует
- Оставьте поле пустым, чтобы использовать образ раннера по умолчанию из `runner.executor.docker.image` или `runner.executor.k8s.image`
- Очистка поля в интерфейсе убирает переопределение

**Сценарии использования**:
- Шаблоны, которым нужен другой набор инструментов (более старый Ansible, конкретная версия Terraform, дополнительные системные пакеты в собственном образе)
- Изолированные образы для шаблонов с повышенными требованиями к безопасности без изменения настройки по умолчанию для всего раннера

Настройки образа по умолчанию описаны в разделе [Конфигурация раннера](/admin-guide/configuration), а настройка исполнителей — в разделе [Раннеры проекта](/user-guide/projects/runners).

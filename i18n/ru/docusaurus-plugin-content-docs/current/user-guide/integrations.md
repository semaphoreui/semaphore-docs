# Интеграции

Интеграции позволяют внешним сервисам — GitHub, GitLab или CI-серверу — запускать задачи в Semaphore, обращаясь к URL вебхука. Интеграцию описывают три объекта: **эндпоинт** задаёт, куда приходит запрос и как он аутентифицируется, **группа интеграций** — какие интеграции запускаются с этого эндпоинта, а **интеграция** — что запускать и с какими параметрами.

![Список интеграций](/assets/integrations-list.webp)

## Как это работает {#how-it-works}

| Объект | Что содержит | Где находится |
|---|---|---|
| **Эндпоинт** | Имя и описание, один или несколько **алиасов** (публичных URL вида `/api/integrations/<random_string>`) и **аутентификацию**, которой проверяется каждый запрос к этим URL. | Проект → **Endpoints** |
| **Группа интеграций** | Набор интеграций, запускаемых с одного эндпоинта. Обычно группа наследует аутентификацию эндпоинта, но может **переопределить** её собственным способом и секретом. | Проект → **Integrations**, по одному разделу на группу |
| **Интеграция** | Шаблон или рабочий процесс (Pro), который нужно запустить, параметры задачи, [сопоставители](#matchers), отфильтровывающие запросы, и [извлечение значений](#value-extractors), передающее данные в задачу. | Внутри своей группы |

Когда запрос приходит на алиас, Semaphore находит эндпоинт, проверяет запрос аутентификацией каждой группы (эндпоинта или собственной группы) и запускает каждую интеграцию авторизованной группы, все сопоставители которой приняли запрос. Интеграция без сопоставителей запускается на каждый авторизованный запрос. Ответ всегда `204 No Content`; заголовки `X-Semaphore-Endpoint-ID`, `X-Semaphore-Integration-Group-ID`, `X-Semaphore-Integration-ID` и `X-Semaphore-Task-ID` сообщают, что было запущено. Принимаются запросы `GET` и `POST`.

![Подробности интеграции](/assets/integration-detail.webp)

Строка алиаса — единственный секрет эндпоинта без аутентификации: обращайтесь с URL как с паролем, а чтобы отозвать доступ, удалите алиас. У одного эндпоинта может быть несколько алиасов, поэтому каждому отправителю можно выдать отдельный URL и отзывать их по одному.

## Аутентификация {#authentication}

Эндпоинт или переопределяющая его группа проверяет запросы одним из следующих способов:

* **GitHub Webhooks** — заголовок `X-Hub-Signature-256`, HMAC-SHA256 тела с секретом
* **Bitbucket Webhooks** — заголовок `x-hub-signature`, HMAC-SHA256 тела
* **Токен** — заголовок на ваш выбор должен совпадать с секретом
* **HMAC (SHA-256)** и **HMAC (SHA-512)** — заголовок на ваш выбор содержит подпись тела
* **BasicAuth** — логин и пароль из учётных данных «логин/пароль»
* **Без аутентификации** — проходит любой запрос с действительным URL алиаса

Секрет берётся из [хранилища ключей](./key-store) проекта: ключ типа **Строка** (секретом является его значение) или учётные данные **«логин/пароль»** (секретом является пароль). Исключение — BasicAuth: он проверяет ещё и логин, поэтому ему нужны учётные данные «логин/пароль». Форма предлагает только ключи подходящего для способа типа, а API отклоняет остальные.

## Аутентификация HMAC {#hmac-authentication}

Методы аутентификации HMAC (`hmac` / SHA-256 и `hmac-sha512` / SHA-512) проверяют, что тело вебхука подписано общим секретом.

Настройте на эндпоинте (или на переопределяющей его группе):

1. **Auth header** — заголовок запроса, в котором передаётся подпись (например, `X-Signature`).
2. **Auth secret** — ключ типа **Строка** из хранилища ключей или учётные данные «логин/пароль».

Отправитель должен поместить в этот заголовок HMAC-дайджест необработанного тела запроса в виде **шестнадцатеричной строки без префикса** `sha256=` или `sha512=`. Semaphore сравнивает его с `HMAC-SHA256` или `HMAC-SHA512` тела, вычисленным с настроенным секретом.

Пример для SHA-512 с OpenSSL:

```bash
SECRET='your-webhook-secret'
BODY='{"event":"deploy"}'
SIG="$(printf '%s' "$BODY" | openssl dgst -sha512 -hmac "$SECRET" | awk '{print $2}')"

curl -X POST "https://semaphore.example.com/api/integrations/<alias>" \
  -H "Content-Type: application/json" \
  -H "X-Signature: ${SIG}" \
  --data "$BODY"
```

## Сопоставители {#matchers}

Сопоставители описывают запросы, на которые реагирует интеграция: заголовок или поле тела (путь JSON или всё тело как строка) сравнивается со значением. Все сопоставители интеграции должны совпасть; интеграция без сопоставителей запускается на каждый запрос, который пропустила её группа. Используйте сопоставители, чтобы запускать разные интеграции одного эндпоинта для разных событий — например, один шаблон для `push`, а другой для `release`.

## Извлечение значений {#value-extractors}

С помощью извлекателя (extractor) можно взять данные из заголовка или тела запроса (поле JSON или строка) и передать их в задачу. У каждого извлечённого значения есть **тип переменной**:

* **Environment**: значение добавляется к переменным окружения задачи и переопределяет одноимённую переменную из группы переменных.
* **Task parameter**: значение становится параметром задачи, например переменной опроса или подсказкой.

## Параметры задачи {#task-parameters}

Интеграции могут запускать задачи с параметрами. Используйте извлечение значений, чтобы сформировать JSON-нагрузку для параметров задачи, и настройте шаблон так, чтобы он принимал запрашиваемые значения.

## Обновление с более ранних версий {#upgrading-from-older-versions}

До версии 2.20.19 у интеграции была собственная аутентификация, а алиасы существовали либо для всего проекта, либо для отдельной интеграции. При обновлении эта конфигурация преобразуется так, что поведение существующих URL не меняется:

| Было | После обновления |
|---|---|
| Алиасы проекта (URL над списком интеграций) | Эндпоинт с именем **Default** без аутентификации, содержащий все эти алиасы |
| Интеграция, доступная через алиас проекта (включено «Use project alias») | Собственная группа на эндпоинте **Default**. Если у интеграции была аутентификация, группа **переопределяет** ею аутентификацию эндпоинта |
| Интеграция с собственными алиасами | Эндпоинт с именем интеграции, с её алиасами и аутентификацией, и собственная группа на этом эндпоинте |
| Сопоставители и извлечение значений | Без изменений |

Каждая интеграция оказывается одна в группе, названной её именем; затем объединяйте группы и переименовывайте эндпоинты как угодно. От прежнего поведения отличаются две детали: интеграция за алиасом проекта без сопоставителей раньше никогда не запускалась, а теперь запускается на каждый авторизованный запрос; собственные алиасы интеграции, которая одновременно использовала алиас проекта (и которые никогда ни на что не срабатывали), удаляются. Резервные копии проекта, сделанные в более ранней версии, при восстановлении преобразуются таким же образом.

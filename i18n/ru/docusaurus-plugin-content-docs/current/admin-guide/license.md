# Активация лицензии <Pro />

Возможности Semaphore Pro и Enterprise включаются с помощью лицензионного ключа. Активировать лицензию можно из веб-интерфейса или указать ключ в конфигурации сервера для автоматизированных развёртываний.

## Перед началом {#before-you-start}

- Для активации Pro или Enterprise не нужно переустанавливать Semaphore UI или переходить на другую сборку. Вашу текущую версию Semaphore UI можно активировать лицензионным ключом. Обновитесь до последней версии, если хотите получить доступ к новейшим возможностям Pro или Enterprise.
- Войдите под учётной записью администратора.
- Подготовьте лицензионный ключ. Его можно найти в письме о покупке или в [портале Semaphore UI](https://portal.semaphoreui.com/auth/login).

## Активация из веб-интерфейса {#activate-from-the-web-ui}

1. Войдите в Semaphore UI как администратор.

![Экран входа в Semaphore UI](/assets/subscription-login-screen.png)

2. Откройте меню администратора из пользовательской области в левом нижнем углу.

![Кнопка меню администратора в левом нижнем углу](/assets/subscription-admin-menu-trigger.png)

3. Выберите **Upgrade to PRO or EE**.

![Меню администратора с пунктом Upgrade to PRO or EE](/assets/subscription-upgrade-menu-item.png)

4. Вставьте лицензионный ключ в диалог активации и нажмите **ACTIVATE NEW KEY**.

![Диалог активации Semaphore Pro](/assets/subscription-activation-dialog.png)

После успешной активации Semaphore UI показывает сведения о текущей лицензии в диалоге **Subscription & Billing**.

![Диалог Subscription and Billing после успешной активации](/assets/subscription-activation-success.png)

## Активация из конфигурации {#activate-from-configuration}

Для Docker, Kubernetes, systemd и других автоматизированных развёртываний укажите лицензионный ключ в конфигурации сервера вместо ввода в UI. Имена опций конфигурации используют префикс `subscription.*`.

В `config.json`:

```json
{
  "subscription": {
    "key": "YOUR_LICENSE_KEY"
  }
}
```

Или как переменная окружения:

```bash
export SEMAPHORE_SUBSCRIPTION_KEY=YOUR_LICENSE_KEY
```

Ключ также можно хранить в файле:

```json
{
  "subscription": {
    "key_file": "/run/secrets/semaphore-license-key"
  }
}
```

или:

```bash
export SEMAPHORE_SUBSCRIPTION_KEY_FILE=/run/secrets/semaphore-license-key
```

Когда лицензионный ключ управляется через конфигурацию, Semaphore UI отключает элементы редактирования и активации в диалоге **Subscription & Billing**. Это относится и к `subscription.key`, и к `subscription.key_file`, поскольку сервер при запуске считывает файл ключа в лицензионный ключ времени выполнения.

## Как работает проверка лицензии {#how-license-validation-works}

Semaphore UI проверяет лицензию на портале Semaphore UI. Адрес задаётся в `subscription.server_url`, по умолчанию — `https://portal.semaphoreui.com/billing`.

### Куда подключается Semaphore UI {#what-semaphore-ui-connects-to}

| Когда | Запрос |
| --- | --- |
| Активация ключа | `POST {server_url}/subscriptions/{key}/activate` |
| Проверка и обновление лицензии | `POST {server_url}/subscriptions/{key}/validate` |

Оба запроса — обычные JSON-запросы, один запрос прерывается через 20 секунд. Запрос активации отправляет лицензионный ключ, запрос проверки — лицензионный токен, который сервер хранит на этот момент. Больше ничего из установки не уходит: учётные записи пользователей, названия проектов, инвентари, имена хостов и вывод задач в эти запросы не входят.

Ответом в обоих случаях является **лицензионный токен** — JWT, подписанный порталом RSA-ключом. Semaphore UI проверяет подпись соответствующим открытым ключом, встроенным в исполняемый файл сервера, поэтому токен нельзя подделать или изменить. В его claims указано, что разрешает лицензия: план, состояние подписки, название компании, дата истечения, а также количество Pro-пользователей, узлов и UI. Сервер хранит ключ и токен в базе данных, в опциях `subscription_key` и `subscription_token`.

### Когда выполняется проверка {#when-the-check-runs}

| Триггер | Что происходит |
| --- | --- |
| Запуск сервера | Лицензионный токен обновляется один раз. |
| Ежедневно в 01:00 по времени сервера | Лицензионный токен обновляется. |
| Активация ключа в веб-интерфейсе или через `subscription.key` | Ключ активируется, в ответ приходит первый токен. |
| **Перезагрузить** в диалоге **Subscription & Billing** | Лицензионный токен обновляется по запросу. |

Между этими вызовами Semaphore UI к порталу не обращается. Любая проверка лицензии — включены ли Pro-функции и поместится ли в лицензию ещё один Pro-пользователь, раннер или состояние HTTP-бэкенда Terraform/OpenTofu — читает сохранённый токен локально.

### Если портал недоступен {#when-the-portal-cannot-be-reached}

Неудачное обновление записывается в лог сервера с контекстом `subscription` и не затрагивает сохранённый токен, поэтому сбой сети или недоступный портал не отключают Pro-функции. Установка продолжает работать, пока не пройдёт дата истечения, указанная в самом токене: просроченный токен всё ещё загружается, но его состояние становится `expired`, и Pro-функции прекращают работать.

### Онлайн- и офлайн-ключи {#online-and-offline-keys}

- **Онлайн-ключ** — это UUID вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. Его активация обращается к порталу, а ежедневное обновление поддерживает его актуальность. Значение, не являющееся UUID, отклоняется до отправки любого запроса.
- **Офлайн-ключ** — это сам лицензионный токен, длинная подписанная строка, выданная для установки без доступа в интернет. Semaphore UI проверяет его локально и никогда не обращается за ним к порталу, поэтому ежедневное обновление не отправляет ни одного запроса. Чтобы продлить офлайн-лицензию, замените ключ на новый выданный.

### Высокая доступность {#high-availability}

Каждый узел сервера обновляет лицензию при своём запуске и по своему ежедневному расписанию и записывает результат в общую базу данных, поэтому все узлы кластера читают один и тот же лицензионный токен. Дополнительная настройка не требуется.

## Доступ к серверу лицензий через прокси {#reach-the-license-server-through-a-proxy}

:::info Начиная с v2.20
Прокси доступен начиная с **Semaphore 2.20**.
:::

Активация ключа, обновление лицензионного токена и ежедневное обновление токена обращаются к порталу Semaphore UI по адресу `subscription.server_url`. В сети, где у сервера нет прямого доступа в интернет, направьте эти запросы через HTTP-прокси:

```json
{
  "subscription": {
    "proxy": {
      "url": "http://proxy.example.com:3128",
      "username": "semaphore",
      "password": "PROXY_PASSWORD"
    }
  }
}
```

Или как переменные окружения:

```bash
export SEMAPHORE_SUBSCRIPTION_PROXY_URL=http://proxy.example.com:3128
export SEMAPHORE_SUBSCRIPTION_PROXY_USERNAME=semaphore
export SEMAPHORE_SUBSCRIPTION_PROXY_PASSWORD=PROXY_PASSWORD
```

Примечания:

- Поддерживаются схемы `http`, `https`, `socks5` и `socks5h`. Неверный адрес прокси останавливает сервер при запуске.
- `username` и `password` необязательны и перекрывают учётные данные, указанные внутри `url`. Отдельные поля не дают паролю попасть в адрес прокси, который Semaphore UI пишет в лог.
- Прокси действует только для запросов к серверу лицензий. Задачи, клонирование Git и другие исходящие соединения он не затрагивает.
- Без `subscription.proxy` сервер лицензий доступен через переменные прокси процесса сервера (`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`), как и раньше.
- Установке без доступа в интернет нужен офлайн-ключ лицензии, а не прокси — для него сервер никогда не обращается к порталу.

## Управление лицензионным ключом и его замена {#manage-or-replace-a-license-key}

Чтобы продлить, заменить или просмотреть лицензию, откройте меню администратора и выберите **Subscription & Billing**.

![Меню администратора с пунктом Subscription and Billing](/assets/subscription-billing-menu-item.png)

Для лицензионного ключа, управляемого из веб-интерфейса, откройте меню действий в диалоге **Subscription & Billing**, чтобы перезагрузить, загрузить или сбросить ключ.

![Диалог Subscription and Billing с действиями над ключом](/assets/subscription-key-actions-menu.png)

Если ключ задан на сервере:

1. Замените значение `subscription.key` или обновите содержимое файла, на который ссылается `subscription.key_file`.
2. Перезапустите Semaphore UI, чтобы сервер перечитал лицензионный ключ.
3. Убедитесь, что ожидаемые возможности Pro или Enterprise доступны в Semaphore UI.

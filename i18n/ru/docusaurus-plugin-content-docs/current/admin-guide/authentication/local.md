# Локальные учётные записи

Локальная учётная запись хранит свой пароль в базе данных Semaphore. Каждая установка
начинается с одной такой записи, созданной командой `semaphore setup` или переменными
`SEMAPHORE_ADMIN_*`, и именно через неё вы попадаете на сервер, пока не появился ни один
провайдер идентификации.

Сохраните хотя бы одного локального администратора даже после того, как заработает единый
вход. Это единственный способ вернуться в систему, когда провайдер идентификации недоступен.

## Как хранятся пароли {#how-passwords-are-stored}

Пароли хешируются алгоритмом **Argon2id** с минимальными параметрами стойкости по
рекомендациям OWASP, а сами параметры записываются рядом с каждым хешем в
[формате строки PHC](https://github.com/P-H-C/phc-string-format/blob/master/phc-sf-spec.md).
Выпуски до 2.20 использовали bcrypt; такие хеши по-прежнему работают, и каждый из них
заменяется хешем Argon2id при следующем успешном входе владельца. Учётные записи, владельцы
которых больше не входят, сохраняют хеш bcrypt, поэтому для их обновления сбросьте пароли.

Полная таблица параметров приведена в разделе [Безопасность](/admin-guide/security#password-hashing).

Semaphore не применяет парольную политику — ни минимальной длины, ни требований к
сложности, ни срока действия. Если политика нужна, используйте каталог или провайдера
идентификации: именно там таким политикам и место.

## Управление учётными записями {#manage-accounts}

Администраторы управляют пользователями в веб-интерфейсе, и те же операции доступны в
командной строке — для скриптов и для восстановления доступа, когда никто не может войти:

```bash
semaphore users add --admin --login jane --name "Jane Doe" \
  --email jane@example.com --password 's3cret'
semaphore users change-by-login --login jane --password 'new-s3cret'
semaphore users list
```

Все флаги описаны в [`semaphore users`](/reference/cli/users), а что даёт роль вошедшему
пользователю — в разделе [Команды](/user-guide/team).

:::warning
Пароль, указанный в командной строке, попадает в историю вашей оболочки и в список процессов
машины. Используйте такой способ для первого администратора и для восстановления доступа, а
затем смените пароль через веб-интерфейс.
:::

## Двухфакторная аутентификация {#two-factor-authentication}

Локальная учётная запись может после пароля запрашивать второй фактор: шестизначный код
TOTP из приложения-аутентификатора. По умолчанию он выключен, включается для сервера
параметром `mfa.totp.enabled` и настраивается каждым пользователем для своей учётной записи.
Как это работает, как это включить, как войти с кодом и как восстановить доступ после потери
телефона, описано в разделе [Двухфакторная аутентификация](/admin-guide/authentication/two-factor).

## Время жизни сессии {#session-lifetime}

Сессию завершают два независимых предела; какой из них наступит первым, тот и выводит
пользователя из системы.

**Тайм-аут бездействия** отсчитывается от последнего запроса. Каждый аутентифицированный
запрос, включая фоновый опрос из открытой вкладки браузера, сбрасывает его. По умолчанию это
168 часов (семь дней):

```json
{
  "auth": {
    "session_inactivity_hours": 8
  }
}
```

**Абсолютный предел** отсчитывается с момента входа, а не с последнего запроса, поэтому
активно используемая сессия тоже завершается:

```json
{
  "auth": {
    "max_session_life_hours": 12
  }
}
```

Значение по умолчанию `0` означает отсутствие абсолютного предела. Задавайте его там, где
общая рабочая станция или требование регулятора обязывают людей проходить аутентификацию
заново по расписанию. Браузер, оставленный открытым на странице, которая опрашивает API,
поддерживает сессию активной, поэтому надёжно завершить такую сессию может только
абсолютный предел.

## Отключение входа по паролю {#turn-password-sign-in-off}

После того как провайдер идентификации настроен и вы убедились, что реальный пользователь
может через него войти, параметр `password_login_disable` полностью отклоняет вход по паролю:

```json
{
  "password_login_disable": true
}
```

LDAP и OpenID Connect это не затрагивает. Существующие локальные учётные записи сохраняют
свои роли и историю; у них просто не остаётся способа пройти аутентификацию.

:::danger
Этот параметр применяется немедленно и действует на каждую локальную учётную запись, включая
вашу. Прежде чем задавать его, убедитесь, что единый вход работает, — именно войдя через
него, а не прочитав журнал. Исправление ошибки означает правку файла конфигурации на сервере
и перезапуск.
:::

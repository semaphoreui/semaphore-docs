# Двухфакторная аутентификация

Двухфакторная аутентификация (2FA) после первого шага входа запрашивает второе
доказательство: шестизначный код из приложения-аутентификатора на телефоне пользователя.
Тогда одного украденного пароля для входа уже недостаточно.

Semaphore реализует второй фактор с помощью TOTP — одноразовых паролей на основе времени,
стандарта, на котором работают Google Authenticator, Microsoft Authenticator, Aegis,
1Password, Bitwarden и подобные приложения. Он доступен во всех редакциях.

## Как это работает {#how-it-works}

Будет ли вход запрашивать код, решают два переключателя:

- **Сервер** должен разрешать TOTP — параметр `mfa.totp.enabled`. По умолчанию он выключен.
- **Учётная запись** должна иметь настроенный TOTP. Каждый пользователь включает его для
  своей учётной записи; он не навязывается всем подряд.

Когда включено и то и другое, вход проходит в два шага:

1. Пользователь входит как обычно — по паролю, через LDAP или через провайдера OpenID
   Connect. Второй фактор действует для всех трёх способов.
2. Semaphore открывает сессию, но помечает её как неподтверждённую и запрашивает код. Пока
   код не принят, каждый вызов API в этой сессии отклоняется с `401` и
   `{"error":"TOTP_REQUIRED"}`.
3. Пользователь вводит код, который показывает приложение. Semaphore сверяет его с секретом,
   сохранённым для учётной записи; верный код подтверждает сессию, и пользователь входит.

Код меняется каждые 30 секунд, а приложение вычисляет его из секрета, полученного один раз —
при настройке учётной записи. Semaphore и телефон никогда не связываются друг с другом,
поэтому телефону не нужно сетевое подключение — только примерно точные часы.

## Включение для сервера {#turn-it-on-for-the-server}

Добавьте раздел `mfa.totp` в файл конфигурации и перезапустите Semaphore:

```json
{
  "mfa": {
    "totp": {
      "enabled": true,
      "allow_recovery": true
    }
  }
}
```

Те же настройки можно задать переменными окружения:

```bash
SEMAPHORE_TOTP_ENABLED=true
SEMAPHORE_TOTP_ALLOW_RECOVERY=true
```

| Параметр | Переменная окружения | Что делает |
|---|---|---|
| `mfa.totp.enabled` | `SEMAPHORE_TOTP_ENABLED` | Позволяет пользователям настраивать TOTP и заставляет вход запрашивать код. Без него эта настройка никому не показывается. |
| `mfa.totp.allow_recovery` | `SEMAPHORE_TOTP_ALLOW_RECOVERY` | Выдаёт каждому пользователю одноразовый [код восстановления](#recovery-code) при настройке TOTP и позволяет войти с ним, если телефон потерян. |
| `mfa.totp.app_name` | `SEMAPHORE_TOTP_ISSUER` | Название издателя, которое приложение-аутентификатор показывает рядом с учётной записью. По умолчанию `Semaphore`. См. предупреждение ниже. |

:::warning ⚠️ `app_name` не используется веб-интерфейсом (2026-11-27)
Учётная запись, настроенная из веб-интерфейса, в приложении-аутентификаторе всегда
подписана как `Semaphore:<email>`, что бы ни было указано в `mfa.totp.app_name`. Настроенное
название использует только
[`semaphore users totp enable`](#manage-the-second-factor-from-the-command-line). Если у вас
больше одного Semaphore, пользователи различают записи по адресу электронной почты или
переименовывают запись в своём приложении.
:::

Все параметры также перечислены в
[справочнике по конфигурации](/reference/configuration).

## Настройка TOTP для своей учётной записи {#set-up-totp-for-your-account}

Сначала установите на телефон приложение-аутентификатор. Затем:

1. Откройте проект, щёлкните своё имя внизу боковой панели и выберите
   **Edit Account**.
2. Откройте вкладку **Security**.
3. В разделе **Two-factor authentication** включите **Time-based one-time password**.
   Semaphore сразу создаёт секрет и показывает его в виде QR-кода.
4. В приложении-аутентификаторе добавьте учётную запись и отсканируйте QR-код. Приложение
   начнёт показывать шестизначный код для `Semaphore`.
5. Если под QR-кодом показан **Recovery code**, скопируйте его кнопкой рядом и сохраните
   в надёжном месте — в менеджере паролей или на бумаге. Он показывается только сейчас.
6. Закройте диалог.

<div style={{maxWidth: 450}}>

![Вкладка Security диалога Edit User с включённой двухфакторной аутентификацией: QR-код для сканирования и код восстановления под ним](/assets/two-factor-enrol.webp)

</div>

Переключатель срабатывает сразу; нажимать **Save** и вводить проверочный код не нужно.
Прежде чем выйти, убедитесь, что приложение показывает код для Semaphore, — следующий вход
его запросит.

Позже вкладку **Security** можно открыть снова, чтобы отсканировать QR-код на втором
устройстве. Код восстановления больше не показывается.

## Вход с кодом {#sign-in-with-a-code}

После шага с паролем, LDAP или единым входом Semaphore показывает **Two-step verification**:

![Экран Two-step verification, запрашивающий шестизначный код из приложения-аутентификатора](/assets/two-factor-verify.webp)

Введите шесть цифр, которые сейчас показывает приложение. Форма отправляется сама после
шестой цифры. Неверный или устаревший код вызывает ошибку и оставляет вас на том же экране;
дождитесь следующего кода и попробуйте снова.

**Return to login** прерывает этот вход и начинает его заново.

## Код восстановления {#recovery-code}

Когда телефон потерян или сброшен, код восстановления позволяет пользователю вернуться в
систему самостоятельно:

1. Войдите по паролю как обычно.
2. На экране **Two-step verification** нажмите **Use recovery code**.
3. Введите код восстановления и нажмите **Send**.

Semaphore выполняет вход и **удаляет TOTP из вашей учётной записи**. Вместе с этим
расходуется и код восстановления. Сразу же настройте TOTP заново, как описано
[выше](#set-up-totp-for-your-account), чтобы получить новый секрет и новый код
восстановления.

**Use recovery code** появляется, только если на сервере включён
`mfa.totp.allow_recovery`. Коды восстановления состоят из 16 символов и хранятся только в
виде хеша bcrypt, поэтому никто — включая администраторов — не сможет потом прочитать код
пользователя.

## Удаление второго фактора {#remove-the-second-factor}

**Своя учётная запись.** Выключите **Time-based one-time password** на вкладке **Security**
в **Edit Account**. TOTP удаляется сразу, и следующий вход запрашивает только первый шаг.
Удалите запись Semaphore и из приложения-аутентификатора; она больше ничему не
соответствует.

**Чужая учётная запись.** Пользователь, который потерял телефон и не имеет кода
восстановления, не может удалить TOTP сам. Администратор или пользователь, чья глобальная
роль позволяет управлять пользователями, открывает **Users**, редактирует этого
пользователя и выключает переключатель на вкладке **Security**. Пользователь входит
только по паролю и настраивает TOTP заново.

### Управление вторым фактором из командной строки {#manage-the-second-factor-from-the-command-line}

На сервере то же самое можно сделать без веб-интерфейса — это пригодится, когда
единственный администратор потерял телефон:

```bash
semaphore users totp disable --login jane
```

`semaphore users totp enable --login jane` настраивает TOTP для пользователя и выводит в
терминал URL `otpauth://`, QR-код и код восстановления; `show` выводит URL и QR-код уже
существующей настройки. Обе команды выводят сам секрет, поэтому запускайте их только там,
где терминал никто больше не видит, и передавайте QR-код владельцу лично. Полный синтаксис
приведён в [`semaphore users`](/reference/cli/users#totp-management).

## Отключение для сервера {#turn-it-off-for-the-server}

Задайте `mfa.totp.enabled` значение `false` или удалите раздел и перезапустите сервер.
После этого вход перестаёт запрашивать коды, а настройка **Two-factor authentication**
исчезает с вкладки **Security**.

Ничьи настройки не удаляются. Включите параметр снова — и каждая учётная запись, где был
TOTP, снова запросит свой код с тем же секретом; сканировать заново ничего не нужно.

## Что нужно знать {#things-to-know}

- **API-токены обходят второй фактор.** Запрос с токеном `Authorization: Bearer` никогда
  не запрашивает код. Токен можно создать только из полностью подтверждённой сессии, но
  токены, существовавшие до настройки TOTP, продолжают работать. Проверьте их на странице
  **API Tokens** после включения TOTP.
- **Semaphore не ограничивает число попыток ввода кода.** Шесть цифр — небольшое
  пространство, поэтому ограничьте частоту запросов к `POST /api/auth/verify` и
  `POST /api/auth/recovery` в своём [обратном прокси](/admin-guide/reverse-proxy).
- **Секрет хранится в базе данных как есть.** Любой, кто может прочитать таблицу
  `user__totp` или резервную копию базы данных, способен генерировать действующие коды для
  каждой учётной записи. Защищайте резервные копии так же, как файл конфигурации.
- **TOTP нельзя сделать обязательным.** В Semaphore нет параметра, который заставлял бы
  пользователей его настраивать. Если ваша политика требует второй фактор для всех,
  применяйте её в провайдере идентификации и выполняйте вход пользователей через
  [OpenID Connect](/admin-guide/authentication/openid).

Настройка, удаление и использование второго фактора записываются в
[журнал аудита](/admin-guide/audit-log) как события `iam.mfa` и `auth.mfa`; их список
приведён в разделе [События аудита](/reference/audit-events).

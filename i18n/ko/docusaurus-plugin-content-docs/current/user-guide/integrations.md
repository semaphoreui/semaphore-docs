# 통합

통합을 사용하면 GitHub, GitLab 또는 CI 서버와 같은 외부 서비스가 웹훅 URL을 호출해 Semaphore에서 작업을 시작할 수 있습니다. 통합은 세 가지 객체로 구성됩니다. **엔드포인트**는 요청이 도착하는 위치와 인증 방식을, **통합 그룹**은 해당 엔드포인트에서 어떤 통합이 실행되는지를, **통합**은 무엇을 어떤 매개변수로 시작할지를 정의합니다.

![통합 목록](/assets/integrations-list.webp)

## 작동 방식 {#how-it-works}

| 객체 | 포함 내용 | 위치 |
|---|---|---|
| **엔드포인트** | 이름과 설명, 하나 이상의 **별칭**(`/api/integrations/<random_string>` 형식의 공개 URL), 그리고 해당 URL로 들어오는 모든 요청을 검사하는 **인증** 방식. | 프로젝트 → **Endpoints** |
| **통합 그룹** | 하나의 엔드포인트에서 실행되는 통합의 집합. 그룹은 기본적으로 엔드포인트의 인증을 상속하지만, 자체 방식과 비밀로 **재정의**할 수 있습니다. | 프로젝트 → **Integrations**, 그룹별 섹션 |
| **통합** | 시작할 템플릿 또는 워크플로우(Pro), 작업 매개변수, 요청을 필터링하는 [매처](#matchers), 작업에 값을 전달하는 [값 추출기](#value-extractors). | 해당 그룹 안 |

요청이 별칭에 도착하면 Semaphore는 엔드포인트를 찾고, 각 그룹의 인증(엔드포인트의 것 또는 그룹 자체의 것)으로 요청을 검사한 뒤, 인증된 그룹에서 모든 매처가 요청을 통과시키는 통합을 모두 시작합니다. 매처가 없는 통합은 인증된 모든 요청에서 실행됩니다. 응답은 항상 `204 No Content`이며, `X-Semaphore-Endpoint-ID`, `X-Semaphore-Integration-Group-ID`, `X-Semaphore-Integration-ID`, `X-Semaphore-Task-ID` 헤더가 무엇이 시작되었는지 알려 줍니다. `GET`과 `POST` 요청을 지원합니다.

![통합 상세 정보](/assets/integration-detail.webp)

인증이 없는 엔드포인트에서 별칭 문자열은 유일한 비밀입니다. URL을 비밀번호처럼 다루고, 접근을 철회하려면 별칭을 삭제하십시오. 하나의 엔드포인트에 여러 별칭을 둘 수 있으므로 발신자마다 별도의 URL을 전달하고 하나씩 철회할 수 있습니다.

## 인증 {#authentication}

엔드포인트(또는 이를 재정의하는 그룹)는 다음 방식 중 하나로 요청을 검사합니다:

* **GitHub 웹훅** — `X-Hub-Signature-256` 헤더, 비밀로 계산한 본문의 HMAC-SHA256
* **Bitbucket 웹훅** — `x-hub-signature` 헤더, 본문의 HMAC-SHA256
* **토큰** — 직접 지정한 헤더의 값이 비밀과 일치해야 함
* **HMAC (SHA-256)** 및 **HMAC (SHA-512)** — 직접 지정한 헤더에 본문의 서명이 포함됨
* **BasicAuth** — 로그인/비밀번호 자격 증명의 로그인과 비밀번호
* **인증 없음** — 유효한 별칭 URL로 들어온 모든 요청이 통과함

비밀은 프로젝트의 [키 저장소](./key-store)에서 가져옵니다. **문자열** 키(그 값이 비밀) 또는 **로그인/비밀번호** 자격 증명(그 비밀번호가 비밀)을 사용합니다. BasicAuth는 예외로, 로그인도 확인하므로 로그인/비밀번호 자격 증명이 필요합니다. 폼에는 방식에 맞는 유형의 키만 표시되며, API는 그 외의 키를 거부합니다.

## HMAC 인증 {#hmac-authentication}

HMAC 인증 방식(`hmac` / SHA-256 및 `hmac-sha512` / SHA-512)은 웹훅 본문이 공유 비밀로 서명되었는지 확인합니다.

엔드포인트(또는 이를 재정의하는 그룹)에서 다음을 설정합니다.

1. **Auth header** — 서명이 포함되는 요청 헤더(예: `X-Signature`).
2. **Auth secret** — 키 저장소의 **문자열** 키 또는 로그인/비밀번호 자격 증명.

발신자는 원본 요청 본문의 HMAC 다이제스트를 **접두사 없는 16진수 값**으로 이 헤더에 넣어야 합니다(`sha256=` / `sha512=` 접두사 제외). Semaphore는 설정된 비밀을 사용해 본문에서 계산한 `HMAC-SHA256` 또는 `HMAC-SHA512` 값과 비교합니다.

OpenSSL을 사용한 SHA-512 예시:

```bash
SECRET='your-webhook-secret'
BODY='{"event":"deploy"}'
SIG="$(printf '%s' "$BODY" | openssl dgst -sha512 -hmac "$SECRET" | awk '{print $2}')"

curl -X POST "https://semaphore.example.com/api/integrations/<alias>" \
  -H "Content-Type: application/json" \
  -H "X-Signature: ${SIG}" \
  --data "$BODY"
```

## 매처 {#matchers}

매처는 통합이 반응하는 요청을 정의합니다. 헤더 또는 본문 필드(JSON 경로 또는 문자열로 된 전체 본문)를 값과 비교합니다. 통합의 모든 매처가 일치해야 하며, 매처가 없는 통합은 그룹이 통과시킨 모든 요청에서 실행됩니다. 매처를 사용하면 하나의 엔드포인트에서 이벤트별로 다른 통합을 실행할 수 있습니다. 예를 들어 `push`에는 한 템플릿을, `release`에는 다른 템플릿을 실행합니다.

## 값 추출기 {#value-extractors}

추출기를 사용하면 요청 헤더나 본문(JSON 필드 또는 문자열)에서 데이터를 가져와 작업에 전달할 수 있습니다. 추출된 각 값에는 **변수 유형**이 있습니다:

* **Environment**: 값이 작업의 환경 변수에 추가되며, 변수 그룹에 있는 같은 이름의 변수를 재정의합니다.
* **Task parameter**: 값이 작업 매개변수가 됩니다. 예를 들어 설문 변수나 프롬프트가 됩니다.

## 작업 매개변수 {#task-parameters}

통합은 매개변수와 함께 작업을 트리거할 수 있습니다. 값 추출기를 사용해 작업 매개변수용 JSON 페이로드를 구성하고, 템플릿이 프롬프트 값을 받을 수 있도록 설정하십시오.

## 이전 버전에서 업그레이드 {#upgrading-from-older-versions}

버전 2.20.19 이전에는 통합이 자체 인증을 가지고 있었고, 별칭은 프로젝트 전체 또는 개별 통합에 속했습니다. 업그레이드하면 기존 URL의 동작을 바꾸지 않고 해당 설정이 다음과 같이 변환됩니다:

| 이전 | 업그레이드 후 |
|---|---|
| 프로젝트 별칭(통합 목록 위의 URL) | 인증이 없는 **Default** 엔드포인트가 모든 별칭을 보관 |
| 프로젝트 별칭을 통해 접근하던 통합("Use project alias" 켜짐) | **Default** 엔드포인트에 속한 자체 그룹. 통합에 인증이 있었다면 그룹이 그 인증으로 엔드포인트의 인증을 **재정의** |
| 자체 별칭을 가진 통합 | 통합의 이름을 딴 엔드포인트(별칭과 인증 포함)와 그 엔드포인트에 속한 자체 그룹 |
| 매처와 값 추출기 | 변경 없음 |

모든 통합은 자신의 이름을 딴 그룹에 단독으로 배치됩니다. 이후 필요에 따라 그룹을 병합하거나 엔드포인트의 이름을 바꾸십시오. 이전 동작과 다른 점은 두 가지입니다. 프로젝트 별칭 뒤에 있으면서 매처가 없던 통합은 이전에는 전혀 실행되지 않았지만 이제 인증된 모든 요청에서 실행되며, 프로젝트 별칭도 함께 사용하던 통합의 자체 별칭(어떤 요청과도 매칭되지 않았음)은 제거됩니다. 이전 버전에서 만든 프로젝트 백업도 복원 시 같은 방식으로 변환됩니다.

# 团队

在 Semaphore UI 中，每个项目（Project）都关联一个**团队（Team）**。只有团队成员和管理员才能访问该项目。团队中的每个成员都会被分配四种内置角色之一，角色决定了其访问级别以及可以执行的操作。

在 **Enterprise** 版中，内置角色可以通过[自定义角色](#extended-rbac-enterprise)进行扩展，从而在特定模板上授予额外的细粒度权限。

:::tip
为避免失去对项目的访问权限，建议至少有两名团队成员拥有 <b>Owner</b> 角色。
:::

项目的 **Team** 分区有两个选项卡：**Members**（用户及其角色）和 **Roles**（自定义角色，Enterprise）。

![团队成员](/assets/team-members.webp)

## 内置角色 {#built-in-roles}

每个团队成员恰好拥有以下四种角色之一：

- **Owner**（所有者）
- **Manager**（管理者）
- **Task Runner**（任务执行者）
- **Guest**（访客）

下面详细介绍每个角色及其权限。

### Owner {#owner}

- **完全权限**<br />
  所有者可以在项目中执行任何操作，包括管理角色、添加/移除成员以及配置任何项目设置。

- **多个所有者**<br />
  一个项目可以有多个所有者，以确保拥有完全权限的人不止一位。

- **自我移除限制**<br />
  如果某位所有者是项目唯一的所有者，则不能移除自己。这可以防止项目陷入没有所有者的状态。

- **管理其他所有者**<br />
  所有者可以管理（包括移除或更改角色）所有团队成员，包括其他所有者。

### Manager {#manager}

- **广泛的项目控制权：**管理者拥有与所有者几乎相同的权限，可以处理大多数日常任务并管理项目环境。

- 管理者**不能**：
  - 删除项目。
  - 移除所有者或更改所有者的角色。

- **典型用例：**将 Manager 角色分配给需要广泛访问权限、但不需要删除项目或管理所有者权力的资深团队成员。

### Task Runner {#task-runner}

- **运行任务：**任务执行者可以执行项目中存在的任何任务模板（Task Templates）。

- **其他资源只读：**虽然可以运行任务，但他们对清单（Inventory）、变量、仓库（Repository）等其他资源只有只读访问权限。

- **典型用例：**需要触发和监控任务、但不需要修改项目设置或管理团队成员的开发人员或 QA 工程师。

### Guest {#guest}

- **只读访问：**访客对所有项目资源拥有只读访问权限（例如查看日志、清单、仪表盘）。

- **无写入权限：**他们不能修改设置、运行任务或更改角色。

- **典型用例：**只需要查看项目状态和详情而不做任何更改的利益相关方或其他协作者。

## 扩展 RBAC <Enterprise /> {#extended-rbac-enterprise}

:::info
扩展 RBAC 在 **Semaphore Enterprise** 版中可用，从 [Semaphore v2.17](https://semaphoreui.com/releases/semaphore-v2_17) 开始提供。
:::

扩展 RBAC 在四种内置角色之上叠加额外的权限。内置角色本身保持不变。如果你没有定义自定义角色，每个项目的行为与社区版完全一致。

借助扩展 RBAC，自定义角色可以授予单独的项目级权限。你还可以为角色授予对选定任务模板的权限。这样就可以让团队成员访问所需的模板，而无需将其提升到更高的内置角色。

### 自定义角色 {#custom-roles}

自定义角色是一组命名的权限，用于补充成员的内置项目角色。每个团队成员都保留其内置角色，自定义角色在此基础上增加权限。

自定义角色有两种作用域：

- **全局角色**在实例级别定义，可在任何项目中使用。
- **项目角色**在单个项目内定义，仅在该项目中可用。

### 权限级别 {#permission-levels}

自定义角色在两个级别授予权限：

- **项目级权限**在整个项目范围内扩展用户的访问权限。你在创建角色时选择这些权限。
- **模板权限**控制对某一个任务模板的操作。将角色添加到模板后，在该模板的 **Permissions** 选项卡中选择这些权限。

### 创建自定义角色 {#create-a-custom-role}

在打开角色表单之前，先选择作用域。

#### 全局角色 {#global-role}

全局角色只需创建一次，即可分配给任何项目中的用户。只有实例管理员才能创建全局角色。

打开左下角的管理员菜单，选择 **Roles**。

在实例范围的角色列表中，选择 **New Role**。

![从管理员菜单打开 Roles，然后选择 New Role](/assets/custom-roles-navigation-to-new-role-annotated-v4.png)

#### 项目角色 {#project-role}

项目角色仅在创建它的项目中可用。项目所有者和管理者可以创建项目角色。

1. 打开项目，进入 **Team** > **Roles**。
2. 选择 **New Role**。

在创建第一个项目角色之前，**Roles** 选项卡是空的。它列出所有项目角色，并包含 **New Role** 按钮。

![](https://www.semaphoreui.com/uploads/v2.17/roles1.webp)

### 配置自定义角色 {#configure-a-custom-role}

两种路径打开的是同一个角色表单。根据团队成员所需的访问权限配置角色。

![带有字段和权限复选框的 New Role 对话框](/assets/custom-roles-global-role-form.jpg)

| 字段 | 说明 |
| --- | --- |
| **Name** | 角色的可读名称。 |
| **Slug** | 用于引用该角色的唯一技术标识符。使用小写字母、数字、下划线或连字符，例如 `release_operator`。 |
| **Permissions** | 该角色授予的项目级权限。 |

#### 项目级权限 {#project-wide-permissions}

只选择该角色需要的项目级权限：

| 权限 | 说明 |
| --- | --- |
| **Can run project tasks** | 运行项目任务。 |
| **Can update project** | 在 **Dashboard** > **Settings** 中编辑项目的基本信息。 |
| **Can manage project resources** | 管理项目资源，例如任务模板、仓库、清单、环境、密钥库（Key Store）条目、计划任务（Schedule）、集成（Integration）和运行器（Runner）。这是项目范围的访问权限，不能限制到单个非模板资源。 |
| **Can manage project users** | 管理项目成员及角色分配。 |

项目级权限不能限制到单个清单、仓库、环境或密钥库条目。任务模板是唯一支持细粒度角色分配的资源类型。

:::tip 仅模板访问
要创建只对选定任务模板增加访问权限的细粒度角色，请不要勾选任何项目级权限。这样该角色本身不会增加任何项目级权限。然后将其添加到所需的模板，并只选择该角色在那里需要的操作。
:::

角色配置完成后，选择 **Save**。

### 配置对特定任务模板的访问权限 {#configure-access-to-specific-task-templates}

模板权限在选定的任务模板上增加访问权限。下面的示例使用一个没有项目级权限的自定义角色。当团队成员只需要对选定模板执行某些操作时，这种最小权限配置非常有用。你也可以为已经授予项目级访问权限的角色添加模板权限。

**打开所需的模板**

1. 打开 **Task Templates**，选择目标模板。
2. 打开 **Permissions** 选项卡。

**Permissions** 选项卡列出已添加到该模板的角色。

![](https://www.semaphoreui.com/uploads/v2.17/roles2.webp)

**添加角色并授予模板权限**

1. 选择 **Add Role**，然后选择要添加到此模板的自定义角色。
2. 只选择该角色需要的模板权限，例如 **Can run tasks** 或 **Can update the template**。

此示例使用之前创建的、没有项目级权限的角色。你可以选择项目中可用的任何自定义角色。

![突出显示所需控件的模板权限对话框](/assets/custom-roles-template-permissions-annotated.png)

要为同一角色授予对其他模板的访问权限，请对每个模板重复以上步骤。

:::note 现有的项目访问权限
模板权限是叠加的。它们只增加访问权限，不会替代或削减用户内置角色或其他自定义角色带来的访问权限。如果用户已经可以运行或更新所有任务模板，添加特定模板的角色不会收窄该权限。
:::

### 在项目中分配自定义角色 {#assign-a-custom-role-in-a-project}

创建并配置好全局角色或项目角色后，将其分配给所需的团队成员：

1. 打开项目，进入 **Team**。
2. 展开所需用户旁边的 **Roles**。
3. 选择自定义角色。

### 当前不支持的功能 {#not-currently-supported}

- **LDAP / OIDC 组映射。**自定义角色按用户分配。不支持将外部目录组映射到自定义角色。
- **非模板资源的细粒度权限。**目前只有模板可以在单个资源级别由自定义角色管控。

## 管理团队成员 {#managing-team-members}

- **邀请新成员：** **Owner** 和 **Manager** 可以邀请新用户加入团队，并为其分配初始角色。

- **更改角色：**所有者始终可以更改任何团队成员的角色。管理者可以更改 **Task Runner** 和 **Guest** 的角色，但**不能**更改其他管理者或所有者的角色。

- **移除成员：**所有者和管理者可以移除角色低于自己的团队成员。
  - 所有者可以移除任何人（包括其他所有者），但如果自己是唯一的所有者，则不能移除自己。
  - 管理者可以移除 **Task Runner** 和 **Guest**，但**不能**移除其他管理者或所有者。

---

## 最佳实践 {#best-practices}

1. **保持冗余：**将 **Owner** 角色分配给至少两个人，以确保持续可访问并避免单点故障。
2. **遵循最小权限原则：**
   - 为团队成员分配完成其任务所需的最低角色。
   - 对只需要有限权限的人使用 **Task Runner** 或 **Guest** 角色。
   - 在 Enterprise 版中，优先使用[自定义角色](#extended-rbac-enterprise)授予对特定模板的访问权限，而不是提升成员的内置角色。
3. **定期审查成员：**
   - 随着团队结构变化，重新评估角色。
   - 对不再需要高级权限的用户撤销访问权限或降低角色。
4. **使用管理者处理日常管理：**
   - 将 Owner 角色保留给拥有最终决定权的小范围人群。
   - 将日常项目管理工作委派给管理者，以降低意外重大更改或删除项目的风险。

## 常见问题 {#frequently-asked-questions}

### 1. 所有者可以移除另一位所有者吗？ {#1-can-an-owner-remove-another-owner}
可以。所有者可以移除任何其他所有者或更改其角色，除非自己是项目中仅剩的所有者。

### 2. 谁可以删除项目？ {#2-who-can-delete-the-project}
只有 **Owner** 可以删除项目。

### 3. 管理者可以添加或移除其他管理者吗？ {#3-can-managers-add-or-remove-other-managers}
不可以。管理者只能添加或移除拥有 **Task Runner** 或 **Guest** 角色的用户。要管理所有者或其他管理者，你必须是所有者。

### 4. 如果我不小心移除了所有的所有者会怎样？ {#4-what-happens-if-i-remove-all-owners-by-accident}
如果移除某位所有者会导致项目没有任何所有者，Semaphore UI 会阻止该操作。项目在任何时候都必须至少有一位所有者。

### 5. 访客可以运行任务吗？ {#5-can-guests-run-tasks}
不可以。访客只有只读访问权限，不能触发或管理任务。在 Enterprise 版中，你可以通过[自定义角色](#extended-rbac-enterprise)授予访客运行单个模板的权限。

### 6. 自定义角色会取代内置角色吗？ {#6-do-custom-roles-replace-the-built-in-roles}
不会。自定义角色在内置角色的基础上扩展额外的项目级和模板级权限。每个团队成员仍然恰好拥有一个内置角色。

### 7. 社区版是否提供扩展 RBAC？ {#7-is-extended-rbac-available-in-the-community-edition}
不提供。扩展 RBAC 需要 **Semaphore Enterprise** 订阅。

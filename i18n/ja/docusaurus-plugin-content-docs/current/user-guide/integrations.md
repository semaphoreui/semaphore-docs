# インテグレーション

インテグレーションを使用すると、GitHub、GitLab、CI サーバーなどの外部サービスが Webhook URL を呼び出して Semaphore のタスクを起動できます。インテグレーションは 3 つのオブジェクトで構成されます。**エンドポイント**はリクエストの到着先と認証方法を、**インテグレーショングループ**はそのエンドポイントからどのインテグレーションを実行するかを、**インテグレーション**は何をどのパラメーターで起動するかを定義します。

![インテグレーションの一覧](/assets/integrations-list.webp)

## 仕組み {#how-it-works}

| オブジェクト | 内容 | 場所 |
|---|---|---|
| **エンドポイント** | 名前と説明、1 つ以上の**エイリアス**（`/api/integrations/<random_string>` 形式の公開 URL）、およびそれらの URL へのすべてのリクエストを検証する**認証**。 | プロジェクト → **エンドポイント** |
| **インテグレーショングループ** | 1 つのエンドポイントから実行されるインテグレーションの集合。通常、グループはエンドポイントの認証を継承しますが、独自の方式とシークレットで**上書き**できます。 | プロジェクト → **インテグレーション**（グループごとに 1 セクション） |
| **インテグレーション** | 起動するテンプレートまたはワークフロー（Pro）、タスクパラメーター、リクエストを絞り込む[マッチャー](#matchers)、タスクに値を渡す[値の抽出ルール](#value-extractors)。 | 所属するグループの中 |

リクエストがエイリアスに到着すると、Semaphore はエンドポイントを特定し、各グループの認証（エンドポイントのもの、またはグループ独自のもの）でリクエストを検証し、認証されたグループのうち、すべてのマッチャーがリクエストを受け入れるインテグレーションをすべて起動します。マッチャーのないインテグレーションは、認証されたすべてのリクエストで実行されます。レスポンスは常に `204 No Content` で、`X-Semaphore-Endpoint-ID`、`X-Semaphore-Integration-Group-ID`、`X-Semaphore-Integration-ID`、`X-Semaphore-Task-ID` ヘッダーが何が起動されたかを示します。`GET` と `POST` を受け付けます。

![インテグレーションの詳細](/assets/integration-detail.webp)

認証なしのエンドポイントでは、エイリアス文字列が唯一のシークレットです。URL をパスワードと同様に扱い、無効化するにはエイリアスを削除してください。1 つのエンドポイントに複数のエイリアスを持たせられるため、送信者ごとに別々の URL を渡し、個別に無効化できます。

## 認証 {#authentication}

エンドポイント、またはそれを上書きするグループは、次のいずれかの方式でリクエストを検証します。

* **GitHub Webhooks** — `X-Hub-Signature-256` ヘッダー。シークレットを用いた本文の HMAC-SHA256
* **Bitbucket Webhooks** — `x-hub-signature` ヘッダー。本文の HMAC-SHA256
* **トークン** — 任意のヘッダーの値がシークレットと一致する必要があります
* **HMAC (SHA-256)** および **HMAC (SHA-512)** — 任意のヘッダーに本文の署名を格納します
* **BasicAuth** — ログイン/パスワード認証情報のログインとパスワード
* **認証なし** — 有効なエイリアス URL へのリクエストはすべて通過します

シークレットはプロジェクトの[キーストア](./key-store)から取得します。**文字列**キー（その値がシークレット）または**ログイン/パスワード**認証情報（そのパスワードがシークレット）を使用します。BasicAuth は例外で、ログインも検証するためログイン/パスワード認証情報が必要です。フォームには方式に合った種類のキーのみが表示され、API はそれ以外を拒否します。

## HMAC 認証 {#hmac-authentication}

HMAC 認証方式（`hmac` / SHA-256 および `hmac-sha512` / SHA-512）は、Webhook の本文が共有シークレットで署名されていることを検証します。

エンドポイント（またはそれを上書きするグループ）で次の項目を設定します。

1. **Auth header** — 署名を格納するリクエストヘッダー（例: `X-Signature`）。
2. **Auth secret** — キーストアの**文字列**キー、またはログイン/パスワード認証情報。

送信側は、未加工のリクエスト本文に対する HMAC ダイジェストを **プレフィックスのない16進数** でこのヘッダーに設定する必要があります（`sha256=` / `sha512=` プレフィックスは付けません）。Semaphore は、設定されたシークレットを使用して本文から計算した `HMAC-SHA256` または `HMAC-SHA512` と比較します。

OpenSSL を使用した SHA-512 の例:

```bash
SECRET='your-webhook-secret'
BODY='{"event":"deploy"}'
SIG="$(printf '%s' "$BODY" | openssl dgst -sha512 -hmac "$SECRET" | awk '{print $2}')"

curl -X POST "https://semaphore.example.com/api/integrations/<alias>" \
  -H "Content-Type: application/json" \
  -H "X-Signature: ${SIG}" \
  --data "$BODY"
```

## マッチャー {#matchers}

マッチャーは、インテグレーションが反応するリクエストを定義します。ヘッダーまたは本文のフィールド（JSON パス、または本文全体を文字列として）を値と比較します。インテグレーションのすべてのマッチャーが一致する必要があります。マッチャーのないインテグレーションは、グループが通過させたすべてのリクエストで実行されます。マッチャーを使うと、1 つのエンドポイントでイベントごとに異なるインテグレーションを実行できます。たとえば `push` には一方のテンプレートを、`release` には別のテンプレートを使用します。

## 値の抽出ルール {#value-extractors}

抽出ルールを使用すると、リクエストのヘッダーまたはボディ（JSON フィールドまたは文字列）からデータを取得し、タスクに渡せます。抽出された各値には **変数の種類** があります。

* **環境変数**: 値がタスクの環境変数に追加され、変数グループの同名の変数を上書きします。
* **タスクパラメーター**: 値がタスクのパラメーター（たとえばサーベイ変数やプロンプト）になります。

## タスクパラメーター {#task-parameters}

インテグレーションは、パラメーター付きでタスクをトリガーできます。値の抽出ルールを使用してタスクパラメーター用の JSON ペイロードを構築し、プロンプトで渡される値を受け取れるようテンプレートを設定してください。

## 以前のバージョンからのアップグレード {#upgrading-from-older-versions}

バージョン 2.20.19 より前では、インテグレーションごとに独自の認証を持ち、エイリアスはプロジェクト全体または個々のインテグレーションのいずれかに存在していました。アップグレードでは、既存の URL の動作を変えずにこの設定を変換します。

| 以前 | アップグレード後 |
|---|---|
| プロジェクトのエイリアス（インテグレーション一覧の上の URL） | それらをすべて保持する、認証なしの **Default** という名前のエンドポイント |
| プロジェクトのエイリアス経由で呼び出されていたインテグレーション（「プロジェクトのエイリアスを使用」が有効） | **Default** エンドポイント上の専用グループ。インテグレーションに認証があった場合、グループはその認証でエンドポイントの認証を**上書き**します |
| 独自のエイリアスを持つインテグレーション | インテグレーションの名前を持つエンドポイント（そのエイリアスと認証を含む）と、そのエンドポイント上の専用グループ |
| マッチャーと値の抽出ルール | 変更なし |

すべてのインテグレーションは、自身の名前を持つグループに単独で配置されます。その後、必要に応じてグループを統合したり、エンドポイントの名前を変更したりできます。以前の動作と異なる点が 2 つあります。プロジェクトのエイリアス配下にあり、マッチャーのなかったインテグレーションは以前は一度も実行されませんでしたが、今後は認証されたすべてのリクエストで実行されます。また、プロジェクトのエイリアスも併用していたインテグレーションの独自エイリアス（何にも一致することがなかったもの）は破棄されます。以前のバージョンで作成したプロジェクトのバックアップも、復元時に同じ方法で変換されます。

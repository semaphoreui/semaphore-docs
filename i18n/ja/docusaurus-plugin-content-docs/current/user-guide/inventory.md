# インベントリ

![インベントリの一覧](/assets/inventory-list.webp)

インベントリは、Ansible がプレイを実行する対象ホストの一覧を含むファイルです。
インベントリには、playbook から使用できる変数も保存されます。インベントリは YAML、JSON、または TOML で保存できます。
インベントリの詳細については、[Ansible のドキュメント](https://docs.ansible.com/ansible/latest/inventory_guide/intro_inventory.html)を参照してください。

Semaphore UI は、Semaphore のユーザーが読み取りアクセス権を持つサーバー上のファイルからインベントリを読み込むか、Web GUI で編集する静的インベントリを使用できます。
Managed インベントリは、ホストと変数をレコードとして保持し、Web GUI で編集します。
また、各インベントリには少なくとも 1 つの認証情報が関連付けられています。
ユーザー認証情報は必須で、Ansible がそのインベントリのホストにログインする際に使用します。sudo 認証情報は、そのホストで権限を昇格するために使用します。
インベントリを作成するには、ユーザー名とログインの組み合わせ、または SSH のいずれかのユーザー認証情報がキーストアに設定されている必要があります。
認証情報の詳細については、本サイトの[キーストア](key-store)セクションを参照してください。

## インベントリの種類 {#inventory-types}

| 種類 | 説明 |
|---|---|
| `static` | Web UI で編集する INI 形式のインベントリです。 |
| `static-yaml` | Web UI で編集する YAML 形式のインベントリです。[NetBox](./inventory/netbox-dynamic-inventory) や [Consul](./inventory/consul-dynamic-inventory) などのプラグインインベントリに使用します。 |
| `file` | インベントリファイルへのパスです。相対パスはテンプレートのリポジトリ内を指し、絶対パスはサーバー上のファイルを指します。ファイルが別の Git リポジトリにある場合は、任意で別途 **インベントリリポジトリ** を選択できます。 |
| `managed` | ホストと変数を Web UI でレコードとして管理します。[Managed インベントリ](#managed-inventory) を参照してください。 |
| `terraform-workspace`、`tofu-workspace`、`terragrunt-workspace` | Ansible のインベントリではなく、[Terraform/OpenTofu](./apps/terraform/workspaces) と [Terragrunt](./apps/terragrunt) テンプレート用のワークスペースです。 |

## インベントリの作成 {#creating-an-inventory}
1. キーストアタブをクリックし、login_password または ssh タイプのキーがあることを確認します
2. インベントリタブをクリックし、「新しいインベントリ」をクリックします
3. インベントリに名前を付け、ドロップダウンから正しいユーザー認証情報を選択します。必要に応じて、正しい sudo 認証情報を選択します
4. インベントリの種類を選択します
  * ファイルを選択した場合は、ファイルの絶対パスを使用します。このファイルが Git リポジトリ内にある場合は、相対パスを使用します。例: `inventory/linux-hosts.yaml`
  * static または static-yaml を選択した場合は、フォームにインベントリを貼り付けるか入力します
  * managed を選択した場合は、先にインベントリを作成し、その後インベントリのページでホストと変数を追加します。[Managed インベントリ](#managed-inventory)を参照してください
5. 「作成」をクリックします。

## インベントリの更新 {#updating-an-inventory}
1. インベントリタブをクリックします
2. 編集したいインベントリの横にある鉛筆アイコンをクリックします
3. 変更を加えます
4. 「保存」をクリックします

Managed インベントリのホストと変数を変更する方法は、[Managed インベントリ](#managed-inventory)を参照してください。

## インベントリの削除 {#deleting-an-inventory}
インベントリを削除する前に、それに関連付けられているすべてのリソースを削除する必要があります。
環境でどのリソースが使用されているかわからない場合は、以下の手順 1 と 2 に従ってください。使用されているリソースが、それらへのリンクとともに表示されます。

1. インベントリタブをクリックします
2. インベントリの横にあるゴミ箱アイコンをクリックします
3. 本当にインベントリを削除してよければ、「はい」をクリックします

## Managed インベントリ {#managed-inventory}

Managed インベントリは、インベントリのテキストではなく、ホストをレコードとして保持します。ホストを頻繁に追加、変更、無効化し、長いテキストを編集したくない場合に使用します。

一覧でインベントリの名前をクリックします。ページには 3 つのタブがあります。

* **Hosts**: ホストを名前で検索し、グループで絞り込み、追加、編集、削除します。**Groups** 列には、ホストが属するグループが表示されます。**Variables** 列には、ホストの変数の数が表示されます。
* **Groups**: ホストのグループです。[グループ](#managed-inventory-groups)を参照してください。
* **Variables**: インベントリ全体の変数です。

ホストには、名前、任意の説明、変数があります。名前は、Ansible がホストとして認識するものです。インベントリ内で一意である必要があり、大文字と小文字は区別されます。スペース、カンマ、角括弧、コロンは使用できません。アドレスとポートは、変数 `ansible_host` と `ansible_port` に設定します。

ホストとインベントリの変数は、マッピングとして YAML または JSON で記述します。

```yaml
ansible_host: 10.0.0.5
ansible_user: deploy
```

ホストに設定した値は、インベントリに設定した同じ変数より優先されます。YAML のアンカー、エイリアス、マージキーは使用できません。

ホストをスキップするには、ホスト一覧でそのスイッチをオフにします。その後に作成されたタスクは、そのホストを使用しません。再び使用するには、スイッチをオンにします。

**Hosts** タブの **Last run** <Pro /> 列には、このインベントリを使った最後のタスクが各ホストでどのように終了したか、およびその日時が表示されます。日時をクリックすると、そのタスクが開きます。まだ実行されていないホストには「never run」と表示されます。実行済みホストの名前をクリックすると、タスク履歴のあるそのホストのページが開きます。名前を変更したホストも最後の実行を保持します。

* 作成後に、インベントリの種類を `managed` に変更したり、`managed` から変更したりすることはできません。
* Managed インベントリのホストと変数は、プロジェクトのバックアップに含まれます。
* プロジェクトの閲覧のみ可能なユーザーは、このページを開けますが、変更はできません。

### グループ {#managed-inventory-groups}

グループを使うと、たとえば `hosts: web` のようにホストの一部に対してプレイブックを実行したり、多くのホストに変数を一度に設定したりできます。

**Groups** タブでグループを追加します。グループには、名前、任意の説明、変数、子グループがあります。名前はインベントリ内で一意である必要があり、`all` と `ungrouped` という名前は予約されています。子グループのホストは、親グループにも属します。グループを自身の祖先にすることはできません。

ホストをグループに入れるには、ホストを追加または編集するときに **Groups** フィールドでグループを選択します。複数のホストをまとめて変更するには、**Hosts** タブでホストを選択し、**Add to groups** または **Remove from groups** をクリックします。1 つのホストを複数のグループに入れることができます。

グループのホストを確認するには、**Hosts** タブのフィルターでグループを選択します。一覧には、子グループのホストも含まれます。

ホストに設定した値は、グループに設定した同じ変数より優先され、グループに設定した値はインベントリより優先されます。グループを対象とするタスクは、そのグループのホストのうち、スイッチがオンのホストで実行されます。

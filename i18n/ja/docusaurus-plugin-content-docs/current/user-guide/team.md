# チーム

Semaphore UI では、すべてのプロジェクトが **チーム** に関連付けられています。プロジェクトにアクセスできるのはチームのメンバーと管理者のみです。チームの各メンバーには 4 つの組み込みロールのいずれかが割り当てられ、それによってアクセスのレベルと実行できる操作が決まります。

**Enterprise** エディションでは、組み込みロールを[カスタムロール](#extended-rbac-enterprise)で拡張し、特定のテンプレートに対するきめ細かな権限を追加で付与できます。

:::tip
プロジェクトへのアクセスを失わないように、<b>オーナー</b> ロールを持つチームメンバーを少なくとも 2 人用意することをおすすめします。
:::

プロジェクトの **チーム** セクションには 2 つのタブがあります。ユーザーとそのロールを表示する **メンバー** と、カスタムロールを表示する **ロール**（Enterprise）です。

![チームのメンバー](/assets/team-members.webp)

## 組み込みロール {#built-in-roles}

チームの各メンバーは、次の 4 つのロールのうち必ず 1 つを持ちます。

- **オーナー**
- **マネージャー**
- **タスクランナー**
- **ゲスト**

以下では、各ロールとその権限を詳しく説明します。

### オーナー {#owner}

- **すべての権限**<br />
  オーナーは、ロールの管理、メンバーの追加・削除、あらゆるプロジェクト設定の構成を含め、プロジェクト内のすべての操作を実行できます。

- **複数のオーナー**<br />
  プロジェクトには複数のオーナーを設定できるため、すべての権限を持つ人を複数確保できます。

- **自分自身の削除に関する制限**<br />
  オーナーがプロジェクトで唯一のオーナーである場合、自分自身を削除できません。これにより、プロジェクトがオーナーのいない状態になることを防ぎます。

- **他のオーナーの管理**<br />
  オーナーは、他のオーナーを含むすべてのチームメンバーを管理できます（削除やロールの変更も可能です）。

### マネージャー {#manager}

- **プロジェクトの広範な管理:** マネージャーはオーナーとほぼ同じ権限を持ち、日常的な作業のほとんどとプロジェクト環境の管理を行えます。

- マネージャーが **できないこと**:
  - プロジェクトを削除する。
  - オーナーを削除する、またはそのロールを変更する。

- **典型的なユースケース:** 広範なアクセスが必要だが、プロジェクトの削除やオーナーの管理の権限までは不要な、経験豊富なチームメンバーにマネージャーロールを割り当てます。

### タスクランナー {#task-runner}

- **タスクの実行:** タスクランナーは、プロジェクト内に存在するあらゆるタスクテンプレートを実行できます。

- **その他のリソースは読み取り専用:** タスクは実行できますが、インベントリ、変数、リポジトリなどのその他のリソースには読み取り専用のアクセスしかありません。

- **典型的なユースケース:** タスクの実行と監視は必要だが、プロジェクト設定の変更やチームメンバーの管理は不要な開発者や QA エンジニアです。

### ゲスト {#guest}

- **読み取り専用のアクセス:** ゲストは、すべてのプロジェクトリソース（ログ、インベントリ、ダッシュボードの閲覧など）に読み取り専用でアクセスできます。

- **書き込み権限なし:** 設定の変更、タスクの実行、ロールの変更はできません。

- **典型的なユースケース:** 変更は行わず、プロジェクトの状況や詳細を閲覧するだけの関係者や協力者です。

---

## 拡張 RBAC（Enterprise） {#extended-rbac-enterprise}

:::info
拡張 RBAC は **Semaphore Enterprise** エディションで、[Semaphore v2.17](https://semaphoreui.com/releases/semaphore-v2_17) 以降で利用できます。
:::

拡張 RBAC は、4 つの組み込みロールの上に追加の権限を重ねるものです。組み込みロール自体は変更されません。カスタムロールを定義しなければ、すべてのプロジェクトはコミュニティエディションとまったく同じように動作します。

拡張 RBAC では、カスタムロールによってプロジェクト全体の個別の権限を付与できます。また、選択したタスクテンプレートに対する権限をロールに付与することもできます。これにより、より上位の組み込みロールに昇格させることなく、チームメンバーに必要なテンプレートへのアクセスを与えられます。

### カスタムロール {#custom-roles}

カスタムロールは、メンバーの組み込みプロジェクトロールを補完する、名前付きの権限のセットです。チームの各メンバーは組み込みロールを保持したままで、カスタムロールはそれに権限を追加します。

カスタムロールは 2 つのスコープで利用できます。

- **グローバルロール** はインスタンスレベルで定義され、あらゆるプロジェクトで使用できます。
- **プロジェクトロール** は単一のプロジェクト内で定義され、そのプロジェクト内でのみ利用できます。

### 権限のレベル {#permission-levels}

カスタムロールは 2 つのレベルで権限を付与します。

- **プロジェクト全体の権限** は、プロジェクト全体にわたってユーザーのアクセスを拡張します。ロールを作成するときに選択します。
- **テンプレートの権限** は、1 つのタスクテンプレートに対する操作を制御します。ロールをテンプレートに追加した後、そのテンプレートの **権限** タブで選択します。

### カスタムロールの作成 {#create-a-custom-role}

ロールのフォームを開く前に、スコープを決めてください。

#### グローバルロール {#global-role}

グローバルロールは一度作成すれば、あらゆるプロジェクトのユーザーに割り当てられます。グローバルロールを作成できるのはインスタンスの管理者のみです。

左下の管理者メニューを開き、**ロール** を選択します。

インスタンス全体のロールの一覧で **新しいロール** を選択します。

![管理者メニューからロールを開き、新しいロールを選択する](/assets/custom-roles-navigation-to-new-role-annotated-v4.png)

#### プロジェクトロール {#project-role}

プロジェクトロールは、作成したプロジェクト内でのみ利用できます。プロジェクトのオーナーとマネージャーが作成できます。

1. プロジェクトを開き、**チーム** > **ロール** に移動します。
2. **新しいロール** を選択します。

**ロール** タブは、最初のプロジェクトロールを作成するまで空です。このタブにはすべてのプロジェクトロールが一覧表示され、**新しいロール** ボタンがあります。

![](https://www.semaphoreui.com/uploads/v2.17/roles1.webp)

### カスタムロールの構成 {#configure-a-custom-role}

どちらの経路でも同じロールのフォームが開きます。チームメンバーに必要なアクセスに合わせてロールを構成してください。

![フィールドと権限のチェックボックスが表示された新しいロールのダイアログ](/assets/custom-roles-global-role-form.jpg)

| フィールド | 説明 |
| --- | --- |
| **名前** | ロールの人が読みやすいラベルです。 |
| **スラッグ** | ロールを参照するために使用する一意の技術的な識別子です。小文字、数字、アンダースコア、ハイフンを使用します。例: `release_operator`。 |
| **権限** | このロールが付与するプロジェクト全体の権限です。 |

#### プロジェクト全体の権限 {#project-wide-permissions}

ロールに必要なプロジェクト全体の権限のみを選択してください。

| 権限 | 説明 |
| --- | --- |
| **プロジェクトのタスクを実行できる** | プロジェクトのタスクを実行します。 |
| **プロジェクトを更新できる** | **ダッシュボード** > **設定** でプロジェクトの基本情報を編集します。 |
| **プロジェクトのリソースを管理できる** | タスクテンプレート、リポジトリ、インベントリ、変数グループ、キーストアのエントリ、スケジュール、インテグレーション、ランナーなどのプロジェクトリソースを管理します。これはプロジェクト全体のアクセスであり、テンプレート以外の個別のリソースに限定することはできません。 |
| **プロジェクトのユーザーを管理できる** | プロジェクトのメンバーとロールの割り当てを管理します。 |

プロジェクト全体の権限は、単一のインベントリ、リポジトリ、変数グループ、キーストアのエントリに限定することはできません。きめ細かなロールの割り当てに対応しているリソースの種類はタスクテンプレートのみです。

:::tip テンプレートのみへのアクセス
選択したタスクテンプレートのみにアクセスを追加するきめ細かなロールを作成するには、プロジェクト全体の権限をすべてチェックしないままにします。そのロールはプロジェクト全体の権限を一切追加しません。必要なテンプレートにそのロールを追加し、そこで必要な操作のみを選択してください。
:::

ロールの構成が完了したら **保存** を選択します。

### 特定のタスクテンプレートへのアクセスを構成する {#configure-access-to-specific-task-templates}

テンプレートの権限は、選択したタスクテンプレートにアクセスを追加します。以下の例では、プロジェクト全体の権限を持たないカスタムロールを使用します。この最小権限の構成は、チームメンバーが選択したテンプレートの操作のみを必要とする場合に便利です。プロジェクト全体のアクセスを既に付与しているロールに、テンプレートの権限を追加することもできます。

**対象のテンプレートを開く**

1. **タスクテンプレート** を開き、対象のテンプレートを選択します。
2. **権限** タブを開きます。

**権限** タブには、そのテンプレートに既に追加されているロールが一覧表示されます。

![](https://www.semaphoreui.com/uploads/v2.17/roles2.webp)

**ロールを追加してテンプレートの権限を付与する**

1. **ロールを追加** を選択し、このテンプレートに追加するカスタムロールを選びます。
2. **タスクを実行できる** や **テンプレートを更新できる** など、そのロールに必要なテンプレートの権限のみを選択します。

この例では、プロジェクト全体の権限を持たない、あらかじめ作成したロールを使用しています。プロジェクトで利用できるカスタムロールであれば、どれでも選択できます。

![必要な操作部分が強調されたテンプレートの権限のダイアログ](/assets/custom-roles-template-permissions-annotated.png)

同じロールに別のテンプレートへのアクセスを付与するには、テンプレートごとにこの手順を繰り返します。

:::note 既存のプロジェクトのアクセス
テンプレートの権限は加算的です。ユーザーの組み込みロールや他のカスタムロールによるアクセスを置き換えたり削減したりすることなく、アクセスを追加します。ユーザーが既にすべてのタスクテンプレートを実行または更新できる場合、テンプレート固有のロールを追加してもそのアクセスが狭まることはありません。
:::

### プロジェクトでカスタムロールを割り当てる {#assign-a-custom-role-in-a-project}

グローバルロールまたはプロジェクトロールを作成して構成した後、対象のチームメンバーに割り当てます。

1. プロジェクトを開き、**チーム** に移動します。
2. 対象のユーザーの横にある **ロール** を展開します。
3. カスタムロールを選択します。

### 現在サポートされていないこと {#not-currently-supported}

- **LDAP / OpenID Connect のグループマッピング。** カスタムロールはユーザーごとに割り当てます。外部ディレクトリのグループをカスタムロールにマッピングすることはサポートされていません。
- **テンプレート以外のリソースに対するきめ細かな権限。** 現時点で、個別のリソース単位でカスタムロールによる制御ができるのはテンプレートのみです。

## チームメンバーの管理 {#managing-team-members}

- **新しいメンバーの招待:** **オーナー** と **マネージャー** は、新しいユーザーをチームに招待し、最初のロールを割り当てられます。

- **ロールの変更:** オーナーは常に、すべてのチームメンバーのロールを変更できます。マネージャーは **タスクランナー** と **ゲスト** のロールを変更できますが、他のマネージャーやオーナーのロールは変更 **できません**。

- **メンバーの削除:** オーナーとマネージャーは、自分より下位のロールのチームメンバーを削除できます。
  - オーナーは誰でも（他のオーナーも含めて）削除できますが、自分が唯一のオーナーである場合は自分自身を削除できません。
  - マネージャーは **タスクランナー** と **ゲスト** を削除できますが、他のマネージャーやオーナーは削除 **できません**。

## ベストプラクティス {#best-practices}

1. **冗長性を確保する:** 継続的なアクセスを確保し、単一障害点を防ぐために、**オーナー** ロールを少なくとも 2 人に割り当てます。
2. **最小権限の原則に従う:**
   - チームメンバーには、作業に必要な最小限のロールを与えます。
   - 限定された権限のみが必要な人には、**タスクランナー** または **ゲスト** のロールを使用します。
   - Enterprise では、メンバーの組み込みロールを昇格させるのではなく、[カスタムロール](#extended-rbac-enterprise)で特定のテンプレートへのアクセスを付与することをおすすめします。
3. **メンバーを定期的に見直す:**
   - チームの体制が変わったら、ロールを再評価します。
   - 上位の権限が不要になったユーザーは、アクセスを取り消すかロールを下げます。
4. **日常的な管理はマネージャーに任せる:**
   - オーナーロールは、最終的な権限を持つ少人数のグループに限定します。
   - 日常的なプロジェクト管理の作業はマネージャーに委任し、重大な変更やプロジェクトの削除が誤って行われるリスクを減らします。

## よくある質問 {#frequently-asked-questions}

### 1. オーナーは他のオーナーを削除できますか？ {#1-can-an-owner-remove-another-owner}
はい。オーナーは他のオーナーを削除したり、そのロールを変更したりできます。ただし、自分がプロジェクトに残る唯一のオーナーである場合は除きます。

### 2. プロジェクトを削除できるのは誰ですか？ {#2-who-can-delete-the-project}
プロジェクトを削除できるのは **オーナー** のみです。

### 3. マネージャーは他のマネージャーを追加・削除できますか？ {#3-can-managers-add-or-remove-other-managers}
いいえ。マネージャーが追加・削除できるのは、**タスクランナー** または **ゲスト** のロールを持つユーザーのみです。オーナーや他のマネージャーを管理するには、オーナーである必要があります。

### 4. 誤ってすべてのオーナーを削除してしまった場合はどうなりますか？ {#4-what-happens-if-i-remove-all-owners-by-accident}
Semaphore UI は、プロジェクトのオーナーが 1 人もいなくなるようなオーナーの削除を防ぎます。常に少なくとも 1 人のオーナーが必要です。

### 5. ゲストはタスクを実行できますか？ {#5-can-guests-run-tasks}
いいえ。ゲストは読み取り専用のアクセスのみで、タスクの実行や管理はできません。Enterprise エディションでは、[カスタムロール](#extended-rbac-enterprise)を使って個別のテンプレートを実行する権限をゲストに付与できます。

### 6. カスタムロールは組み込みロールを置き換えますか？ {#6-do-custom-roles-replace-the-built-in-roles}
いいえ。カスタムロールは、プロジェクトレベルおよびテンプレートレベルの追加の権限で組み込みロールを拡張します。チームの各メンバーは、引き続き必ず 1 つの組み込みロールを持ちます。

### 7. 拡張 RBAC はコミュニティエディションで利用できますか？ {#7-is-extended-rbac-available-in-the-community-edition}
いいえ。拡張 RBAC には **Semaphore Enterprise** のサブスクリプションが必要です。

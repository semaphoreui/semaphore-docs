# タスク

タスクは[タスクテンプレート](./task-templates)の 1 回の実行です。Ansible playbook、Terraform/OpenTofu/Terragrunt の構成、または Bash、PowerShell、Python のスクリプトを 1 回実行したものを指します。各タスクは独自のログ、ステータス、詳細を保持するため、何がいつ誰によって、リポジトリのどのリビジョンで実行されたかをいつでも確認できます。

## タスクの開始 {#starting-a-task}

プロジェクトで **タスクランナー** 以上のロールが必要です（[チーム](./team)を参照）。タスクは次の 2 か所から開始できます。

- **タスクテンプレート** で、テンプレートの行にある **再生** ボタンをクリックします。
- テンプレートのページで、右上隅のボタンをクリックします。ラベルはテンプレートの種類に応じて **実行**、**ビルド**、**デプロイ** のいずれかになります。

どちらの場合も **新しいタスク** のダイアログが開きます。その内容は、アプリケーションとテンプレートで有効にしたオプションによって異なります。

![Ansible テンプレートの新しいタスクのダイアログ](/assets/task-new-ansible.webp)

| フィールド | 表示される対象 | 説明 |
|---|---|---|
| **メッセージ** | すべてのテンプレート | 任意のメモです。タスクとともに保存され、履歴とアラートに表示されます。 |
| **ビルドバージョン** | デプロイテンプレート | デプロイするビルドです。既定では最新の成功したビルドが選択されます。[ビルド・デプロイテンプレート](./task-templates/build-deploy)を参照してください。 |
| サーベイ変数 | [サーベイ変数](./task-templates/survey-vars)があるテンプレート | 変数ごとに 1 つの入力項目です。必須の変数は入力する必要があります。 |
| **ドライラン** `--check`、**差分** `--diff` | Ansible | playbook をチェックモードで実行する、またはファイルの変更を表示します。その他の Ansible のプロンプト（Limit、Tags、Skip tags、Debug）は、テンプレートで有効にすると表示されます。[プロンプト](./task-templates/prompts)を参照してください。 |
| **Plan**、**Destroy**、**Auto Approve**、**Upgrade**、**Reconfigure** | Terraform、OpenTofu、Terragrunt | `plan` のみを実行する、または `-destroy`、`-auto-approve`、`-upgrade`、`-reconfigure` を追加します。[Terraform/OpenTofu](./apps/terraform) を参照してください。 |
| **ブランチ**、**インベントリ**、**CLI 引数** | すべてのアプリケーション | この実行に限りテンプレートの値を上書きします。各上書きはテンプレートの設定で許可されている必要があります。 |

![Terraform テンプレートの新しいタスクのダイアログ](/assets/task-new-terraform.webp)

**実行**（または **ビルド** / **デプロイ**）をクリックすると、タスクがキューに入ります。

### キューと並列実行 {#queue-and-parallel-execution}

同じテンプレートのタスクは、テンプレートで **並列タスクを許可する** が有効になっていない限り順番に実行されます。また、[プロジェクトの設定](./projects/settings)の **並列タスクの最大数** で、プロジェクト全体の実行中タスク数を制限することもできます。待機が必要なタスクは `waiting` のステータスのまま、空きができると自動的に開始されます。

## タスクのウィンドウ {#task-window}

UI 上のどこかでタスクをクリックすると、タスクのウィンドウが開きます。ヘッダーには、テンプレート、タスク番号、リポジトリのリビジョンのコミットメッセージ、ステータスバッジ、タスクを開始したユーザーと開始時刻、所要時間が表示されます。矢印のアイコンでウィンドウを全画面に拡大できます。

![タスクのログ](/assets/task-log.webp)

| タブ | 内容 |
|---|---|
| **ログ** | タイムスタンプ付きのタスクの出力です。タスクの実行中はログがストリーミングされます。**生ログ** は未加工の出力を新しいブラウザータブで開きます。 |
| **詳細** | テンプレートの情報（アプリケーション、テンプレート）、コミットの情報（メッセージとハッシュ）、および実行の情報（メッセージ、作成時刻、開始時刻、終了時刻、所要時間、設定されている場合はランナー、ブランチ、limit、実行に使用された変数）です。 |
| **サマリー** (Pro) | Ansible のタスクの場合: 正常に完了したホスト数と失敗したホスト数、およびサーバーごとの失敗したタスクの表です。 |

![タスクの詳細](/assets/task-details.webp)

![タスクのサマリー](/assets/task-summary.webp)

## タスクのステータス {#task-statuses}

| ステータス | 意味 |
|---|---|
| `waiting` | タスクはキューに入っています。同じテンプレートの別のタスクが実行中、プロジェクトの上限に達している、または利用できるランナーがまだありません。 |
| `starting` | ランナーがタスクを取得し、リポジトリと環境を準備しています。 |
| `waiting_confirmation` | ツールが質問を表示し、ユーザーの応答を待っています。たとえば **Auto Approve** なしの `terraform apply` や、入力を読み取るスクリプトの場合です。タスクのウィンドウで **承認** または **却下** を使用します。 |
| `confirmed` | ユーザーが質問に承認しました。タスクは続行します。 |
| `rejected` | ユーザーが質問を却下しました。タスクは終了します。 |
| `running` | playbook またはスクリプトを実行しています。 |
| `stopping` | 停止が要求され、プロセスを終了させています。 |
| `stopped` | タスクはユーザーによって停止されました。 |
| `success` | 終了コード 0 で完了しました。 |
| `error` | 0 以外の終了コードで完了した、または開始に失敗しました。UI では **失敗** と表示されます。 |

## タスクの停止 {#stopping-tasks}

実行中のタスクのウィンドウを開き、**停止** をクリックします。Semaphore が終了シグナルを送信し、プロセスが終了するまでタスクは `stopping` のステータスになります。プロセスが反応しない場合、ボタンが **強制停止** に変わります。これをクリックすると、プロセスを即座に強制終了します。

1 つのテンプレートの実行中およびキュー待ちのすべてのタスクを停止するには、テンプレートのページを開いて **すべて停止** を使用します。ドロップダウンには **停止** と **強制停止** の両方が用意されています。

## タスクを再実行する {#running-a-task-again}

テンプレートの **タスク** タブでは、各行に **再実行** ボタンがあります。これをクリックすると、そのタスクのメッセージとパラメーターが入力された状態で新しいタスクのダイアログが開きます。

![再実行ボタンが表示されたテンプレートのタスク](/assets/template-tasks.webp)

## タスクが一覧表示される場所 {#where-tasks-are-listed}

- **ダッシュボード → 履歴**: プロジェクトのすべてのタスクです。[履歴](./projects/history)を参照してください。
- **テンプレートのページ → タスク**: 1 つのテンプレートのタスクです。
- **タスクテンプレート**: 行の左側にある矢印で展開すると、一覧から離れずにそのテンプレートの直近のタスクを確認できます。

## ログの保持 {#log-retention}

既定では、タスクとログは無期限に保持されます。各テンプレートの直近のタスクのみを保持するには `max_tasks_per_template` を使用します。[履歴](./projects/history#task-retention)を参照してください。

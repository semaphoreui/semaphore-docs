# 通知

Semaphore はタスクの結果をチャットとメールに二つの方法で通知します。

- **サーバーチャネル** はサーバー上で一度だけ `config.json` または環境変数で設定され、すべてのプロジェクトで利用できます。このページで説明します。
- **プロジェクトアラート** は、プロジェクトメンバーがプロジェクトの [アラート](/user-guide/alerts) タブで作成する名前付きの送信先で、独自のチャット、Webhook、宛先を持ち、テンプレートやスケジュールに紐付けます。

## 配信の仕組み {#how-delivery-works}

サーバーチャネルでは三つの設定がメッセージ送信の可否を決め、三つすべてが許可している必要があります。

1. **チャネルがサーバーで設定されている。** 各プロバイダーには `config.json` に固有のキーがあります。下記の各プロバイダーのページを参照してください。
2. **プロジェクトがサーバーチャネルを使う。** プロジェクトの [アラート](/user-guide/alerts#server-channels) タブの *このプロジェクトのアラートをサーバーチャネルに送信* がメインスイッチです。オフの場合、サーバーチャネルはそのプロジェクトについて何も送りません。プロジェクトアラートはこのスイッチの影響を受けません。
3. **テンプレートが通知を求めている。** *プロジェクトの既定* を使うテンプレートはサーバーチャネルに送り、独自のアラート一覧を持つテンプレートは送りません。テンプレートは成功または失敗の通知を抑制することもできます。[タスクテンプレート](/user-guide/task-templates) を参照してください。

チャットチャネルは成功、失敗、確認待ちのタスクを通知し、メールは失敗のみ通知します。プロジェクトアラートは送信先ごとにイベントを上書きできます。

アラートタブの **すべてテスト** を使うと、タスクを実行せずにすべてのサーバーチャネルと有効なプロジェクトアラートへテストメッセージを送れます。

## チャネル {#channels}

| チャネル | ページ |
|---|---|
| メール (SMTP) | [Email](/admin-guide/notifications/email) |
| Telegram | [Telegram](/admin-guide/notifications/telegram) |
| Slack | [Slack](/admin-guide/notifications/slack) |
| Microsoft Teams | [Teams](/admin-guide/notifications/teams) |
| Rocket.Chat | [Rocket.Chat](/admin-guide/notifications/rocket) |
| DingTalk | [DingTalk](/admin-guide/notifications/ding) |
| Gotify | [Gotify](/admin-guide/notifications/gotify) |

複数のチャネルを同時に有効にでき、それぞれが上記三つの条件を満たすすべてのアラートを受け取ります。同じプロバイダーをプロジェクトアラートでも使えます。メールと Telegram のプロジェクトアラートはサーバー設定の SMTP サーバーとボットトークンを再利用し、独自の URL とトークンを持たない Gotify のプロジェクトアラートはサーバー全体の組み合わせを再利用します。

## プロジェクトごとの上書き {#per-project-overrides}

Telegram はプロジェクトごとのチャットに対応しています。プロジェクトの [アラート](/user-guide/alerts#server-channels) タブで **Telegram Chat ID** を設定すると、そのプロジェクトのサーバーチャネルのメッセージをサーバー全体とは別のチャットに送れます。それ以外のプロジェクトごとの送信先には [プロジェクトアラート](/user-guide/alerts#project-alerts) を作成してください。

## 始め方 {#where-to-start}

まず一つのチャネルを設定し、プロジェクトのアラートタブを開いて *このプロジェクトのアラートをサーバーチャネルに送信* をオンにし、**すべてテスト** を押します。テストメッセージが届いたら、必要なテンプレートを調整します。
